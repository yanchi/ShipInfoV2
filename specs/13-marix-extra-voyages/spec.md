# Feature Specification: マリックスラインの臨時便を港別ステータスに出す

**Feature Branch**: `13-marix-extra-voyages`
**Created**: 2026-10-26
**Status**: Draft
**Input**: User description: "マリックスラインの臨時便を読めるようにする。公式の詳細ページで臨時便の港は class に temporary が付く（例: 2026-09-06 下り service6727「臨時便・航行経路変更」、2026-09-07 上り service6731「臨時便運航」）が、今は未知クラスで unknown になる。さらに定期便が欠航で、同じ船・同じ出港日・同じ港の臨時便に置き換わる場合（2026-09-07 那覇発 クイーンコーラルクロス、定期便 upstream20260907 は欠航）、departure_statuses の一意キー（route, port, departure_date, ship_name）が衝突し、公式一覧の並び順で先に来た方だけが残る（欠航が残る or 臨時便の不明が残る）。航路単位（operation_statuses）も同じ route×日付で先着になる。期待: temporary を前の機能（12-marue-extra-voyages）の新状態「臨時便」として読む。同じキーが衝突したら臨時便を欠航の定期便より優先して置き換える。航路単位も欠航の定期便より臨時便を優先し、トップには欠航バッジのまま「臨時便 那覇 07:00発」のように添える（12 の US5 と同じ）。寄港しない港（no_status）は skipped のまま。実データは 2026-09-06/07 の公式ページを fixture にして再現する。"

## 概要

マリックスラインは、台風などで定期便が欠航したとき、代わりの臨時便を出す。マルエーフェリーと違い、臨時便は公式の運航状況の一覧に定期便と同じ形で出る。便ごとの詳細ページもあり、本サイトはすでに両方を取っている。

ただ、本サイトは臨時便を読めていない。

- 臨時便の港には、公式が「臨時便」の印（一覧・詳細ページの `temporary`）を付けている。本サイトはこれを知らないので、状態が「不明」になる
- 欠航した定期便と臨時便が同じ船・同じ日・同じ港になることがある（定期便の代わりに、同じ船が臨時便として出る）。本サイトの港別の行は「航路・港・出港日・船」で1つなので、片方しか持てない。今はどちらが残るかが公式一覧の並び順で決まる
- 航路単位（トップのバッジ）も、同じ方向・同じ日の便のうち一覧で先に来た方を使う。臨時便が先だと「不明」になる

12-marue-extra-voyages で、港別の状態「臨時便」と、トップの会社カードの「◆ 臨時便 鹿児島 16:00発」はできている。どちらも会社を問わない作りなので、マリックスラインの臨時便を「臨時便」の行として書けば、港別ページ・トップ・通知メールにそのまま出る。

### 公式サイトで確かめた臨時便（2026-08〜09）

| 日付・方向 | 便（詳細ページ） | 船 | 寄港する港（出港時刻） | 同じ日の定期便 |
|---|---|---|---|---|
| 9/6 下り | 臨時便・航行経路変更（service6727） | クロス | 鹿児島 09:00 → 那覇（9/7 05:00 着） | 航行経路変更・条件付運航（downstream20260906、**プラス**、鹿児島 18:00） |
| 9/7 上り | 臨時便運航（service6731） | クロス | 那覇 07:00 → 名瀬 21:20 → 鹿児島（9/8 08:30 着） | **欠航**（upstream20260907、**クロス**、那覇 07:00・名瀬 21:20） |
| 9/27 上り | 臨時便（service6819） | クロス | **名瀬** 05:50 → 鹿児島（17:00 着） | — |
| 8/27 下り | 臨時便（service6664） | クロス | 鹿児島 10:00 → 那覇（8/28 06:00 着） | — |

- 寄港する港は `temporary`（始発港は `firstport temporary`）、寄港しない港は `no_status`（「―」「寄港しません」）
- 寄港しない港の入出港時刻は、定期便の時刻のまま残っていたり、別の日付（9/27 の便に「08月25日」）が残っていたりする。当てにならない
- 9/27 の便は那覇ではなく名瀬から出る。見出しは「名瀬港発 鹿児島新港向け 上り便」
- 一覧の CSS に `.up_stream_services .temporary`・`.down_stream_services .temporary` の並び順の指定がある。臨時便は一覧でも `temporary` のクラスで、上り・下りの欄に出ると考えられる（2026-10-26 時点の一覧に臨時便が無いので、実物の一覧の HTML は未確認）
- 過去の便の一覧（「過去の運航状況」）には臨時便が出ない

### 2026-09-06・09-07 を今の作りで再現した結果

上の詳細ページと、それを並べた一覧（臨時便のクラスは `temporary alert` と仮定）を、今のスクレイパーに読ませた。

| | 一覧で定期便が先 | 一覧で臨時便が先 |
|---|---|---|
| 9/6 下り・航路単位 | 条件付運航 | **不明** |
| 9/6 下り・鹿児島（クロス 09:00） | **不明** | **不明** |
| 9/7 上り・航路単位 | 欠航 | **不明** |
| 9/7 上り・那覇・名瀬（クロス） | 欠航（**臨時便が消える**） | **不明**（欠航が消える） |
| 9/7 上り・本部・与論・和泊・亀徳（クロス） | 欠航 | 抜港 |

9/7 は、乗れる臨時便があるのに「欠航」と出るか、何も分からない「不明」と出る。台風のあとにいちばん見られる日に、どちらに転んでも間違いになる。

## Clarifications

### Session 2026-10-26

- Q: 臨時便が寄港しない港（詳細ページの「寄港しません」）に、臨時便から行を作る？ → A: マルエーフェリー（12-marue-extra-voyages）に合わせて作らない。同じキーの定期便の行（欠航など）があればそれを残す（FR-003）
- Q: 始発港から出る臨時便しか無い日（8/27 型。航路単位は定期便が無いので「便なし」）、トップのバッジは？ → A: 「臨時便」にする。今は「— 便なし」と「◆ 臨時便 鹿児島 10:00発」が並んで食い違う。マルエーフェリーにも同じく効かせる（FR-014）
- Q: 定期便の詳細ページが取れなかった回の「欠航（船名なし）」の行が、臨時便の行と同じ港に並ぶのは？ → A: 並べたままにする（PR #89 レビューで見直し）。予備ルートの行は船名が分からないので、臨時便と同じ船か決められない。(航路, 港, 出港日) で抑えると、9/6 のように同じ港・同じ日を出る別の船（プラス）の行まで消える。並ぶのは定期便の詳細ページが取れない回だけで、次に取れた回に船名なしの行は消える（FR-015）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 欠航の定期便を置き換えた臨時便が出る (Priority: P1)

9/7 那覇発の定期便（クロス）が欠航になった。公式は、同じクロスで那覇 07:00 発の臨時便を出した。利用者が 9/7 に那覇港の港別ページを見ると、クロスの那覇 07:00 発が「臨時便」で出る。名瀬港の港別ページにも、名瀬 21:20 発が「臨時便」で出る。

**Why this priority**: 今回の穴そのもの。今は一覧の並び順しだいで「欠航」か「不明」になる。「欠航」と出ると、乗れる便があるのに乗れないと思わせる。

**Independent Test**: 9/7 の定期便（欠航）と臨時便の詳細ページを、一覧の並び順を入れ替えて2通り読ませる。どちらの順でも、那覇・名瀬のクロスの行が「臨時便」になり、出港時刻が臨時便の時刻（那覇 07:00、名瀬 21:20）になることを確かめられる。

**Acceptance Scenarios**:

1. **Given** 一覧に 9/7 那覇発の定期便（欠航・クロス）と臨時便（クロス）があり、臨時便が那覇・名瀬に寄る, **When** スクレイパーが動く, **Then** 那覇（9/7 07:00）・名瀬（9/7 21:20）のクロスの行は「臨時便」で、出港時刻は臨時便の詳細ページのとおり
2. **Given** 同じデータで一覧の並び順が逆, **When** スクレイパーが動く, **Then** 結果は 1 と同じ
3. **Given** 同じデータ, **When** スクレイパーが動く, **Then** 臨時便が寄らない本部・与論・和泊・亀徳のクロスの行は、定期便のとおり「欠航」
4. **Given** 前回の実行で那覇のクロスの行を「臨時便」にした, **When** 次の実行で、臨時便は一覧にあるが詳細ページが取れず、定期便（欠航）は読める, **Then** 行は「臨時便」のまま（欠航で上書きしない）
5. **Given** 前回の実行で那覇のクロスの行を「臨時便」にし、臨時便は那覇を出港した, **When** 次の実行で臨時便が一覧から消え、定期便（欠航）だけが残る, **Then** 行は「臨時便」のまま
6. **Given** 前回の実行で那覇のクロスの行を「臨時便」にした, **When** 臨時便が那覇を出港する前に一覧から消え、定期便（欠航）だけが残る, **Then** 行は定期便の「欠航」に戻る（臨時便が取りやめになったとみなす）

### User Story 2 - 臨時便の港が「臨時便」で出る (Priority: P1)

9/6、鹿児島港の港別ページに、定期便（プラス・18:00・条件付運航）と、臨時便（クロス・09:00）が並ぶ。臨時便は「臨時便」のバッジで出る。今は「不明」。

**Why this priority**: 臨時便は、ほかの便と違う時刻・寄港地で走る。「不明」では乗れるかどうか分からない。US1 と同じ読み取りなので一緒に出す。

**Independent Test**: 9/6 の定期便と臨時便の詳細ページを読ませ、鹿児島のクロス 09:00 の行が「臨時便」になり、プラスの行は今までどおり「条件付運航」であることを確かめられる。

**Acceptance Scenarios**:

1. **Given** 臨時便の詳細ページで、寄港する港に臨時便の印がある, **When** スクレイパーが動く, **Then** その港の行は「臨時便」で、出港時刻・到着予定は詳細ページのとおり（鹿児島 9/6 09:00、那覇 9/7 05:00 着）
2. **Given** 臨時便の行ができた, **When** 港別ページ・会社詳細ページを見る, **Then** 「臨時便」のバッジで出て、詳細に公式の説明（「臨時便で時間を変更し、航行経路を「鹿児島 → 那覇」に変更して運航します」など）が入る
3. **Given** 同じ日の定期便が別の船（プラス）, **When** スクレイパーが動く, **Then** 定期便の行は今までどおり（条件付運航・寄港しない港は抜港）

### User Story 3 - 臨時便が寄らない港に、臨時便の行を作らない (Priority: P1)

9/6 の臨時便（クロス）は、鹿児島から那覇へ直行する。今は、名瀬港の港別ページに、乗る予定の無いクロスの「抜港」が出る。しかもその「抜港」は、詳細ページに残った定期便の時刻（9/6 20:50）で出る。9/27 の臨時便だと、寄らない港に「08月25日」の時刻が残っていて、翌年 8/25 の「抜港」の行ができる。直した後は、寄らない港に臨時便の行が出ない。

**Why this priority**: 寄らない港に、乗る予定の無い便の「抜港」が、でたらめな日付で出る。US1・US2 と同じ詳細ページで起きるので一緒に直す。

**Independent Test**: 9/6・9/27 の臨時便の詳細ページを読ませ、寄港しない港の行が1つもできないことを確かめられる。

**Acceptance Scenarios**:

1. **Given** 臨時便の詳細ページで、名瀬・亀徳・和泊・与論・本部が「寄港しません」, **When** スクレイパーが動く, **Then** その5港には臨時便からの行を作らない
2. **Given** 9/27 の臨時便で、寄港しない港の時刻が「08月25日」, **When** スクレイパーが動く, **Then** 8/25 の行（どの年でも）を作らない
3. **Given** 前回の実行で、臨時便が名瀬に寄る予定で名瀬の「臨時便」の行を作った, **When** 次の実行で、臨時便の詳細ページの名瀬が「寄港しません」になる, **Then** 名瀬の臨時便の行は消える

### User Story 4 - 途中の港から出る臨時便が出る (Priority: P2)

9/27、公式は名瀬 05:50 発の鹿児島行き臨時便（上り）を出した。名瀬港の港別ページに出る。トップの会社カードには、上りに「◆ 臨時便 名瀬 05:50発」が出る。

**Why this priority**: 今は「那覇発」「鹿児島発」以外の便の方向が分からず、便ごと読み飛ばしている。台風で那覇まで行けないときの便なので、名瀬の利用者には大事。ただ US1〜US3 より出る回数が少ない。

**Independent Test**: 9/27 の臨時便を一覧の上りの欄に置いて読ませ、上りの航路の名瀬の行（9/27 05:50・臨時便）ができることを確かめられる。

**Acceptance Scenarios**:

1. **Given** 一覧の上りの欄に「名瀬港発 鹿児島新港向け」の臨時便がある, **When** スクレイパーが動く, **Then** 上りの航路に名瀬の行（9/27 05:50・臨時便）ができる。終点の鹿児島（入港だけ）の行は作らない
2. **Given** その日に上りの定期便が無い, **When** 9/27 にトップを見る, **Then** 上りの行は「臨時便」のバッジと「◆ 臨時便 名瀬 05:50発」（12 の FR-016 のとおり）
3. **Given** その日に下りの定期便が無く、鹿児島 10:00 発の臨時便だけがある（8/27 型）, **When** 8/27 にトップを見る, **Then** 下りの行は「臨時便」のバッジと「◆ 臨時便 鹿児島 10:00発」。「便なし」は出さない

### User Story 5 - トップのバッジは定期便で決まり、臨時便は添えて出る (Priority: P2)

9/7 にトップを見ると、マリックスラインの上りは「欠航」のバッジ、その下に「◆ 臨時便 那覇 07:00発」が出る。9/6 の下りは「条件付運航」のバッジ、その下に「◆ 臨時便 鹿児島 09:00発」が出る。

**Why this priority**: 今は一覧の並び順で、トップのバッジが「不明」になる。12 で臨時便の行を添える仕組みはできているので、航路単位を定期便で決めるだけでいい。

**Independent Test**: 9/6・9/7 の一覧を、並び順を入れ替えて読ませ、航路単位の状態が定期便のもの（9/6 下り：条件付運航、9/7 上り：欠航）になることを確かめられる。

**Acceptance Scenarios**:

1. **Given** 一覧に同じ方向・同じ日の定期便と臨時便がある, **When** スクレイパーが動く, **Then** 航路単位の状態は定期便のもの。並び順で変わらない
2. **Given** その方向・その日に臨時便しか無い（9/27 上り）, **When** スクレイパーが動く, **Then** 航路単位は臨時便から書かない（今日なら今までどおり「便なし」）
3. **Given** 9/7 の上りの航路単位が「欠航」で、今日の上りに臨時便の行（那覇 07:00）がある, **When** トップを見る, **Then** 「欠航」のバッジと「◆ 臨時便 那覇 07:00発」が両方出る。欠航の注意書きも今までどおり出る

### Edge Cases

- **定期便が走るのに、同じ船・港・出港日の臨時便がある**（定期便が通常運航・条件付・航行経路変更で、同じ日に同じ船が同じ港から臨時便でも出る）：港別の行は1つしか持てない。定期便の行を残し、その行の詳細に「（臨時便 HH:MM発あり）」を足して警告を出す（12 の R7 と同じ扱い）。2025-10〜2026-10 の公式の記録では起きていない
- **臨時便そのものが欠航になる**（臨時便の詳細ページの港が欠航などのクラス）：寄港する港（「寄港しません」でない港）の行を、その港のクラスどおりの状態で作る。同じキーの定期便の行より臨時便の行を優先する（US1 と同じ）
- **定期便の詳細ページが取れない**（予備ルートが船名なしの行を作る）：今までどおり作る。臨時便の行と同じ港・日付に並ぶことがあるが、次に定期便の詳細ページが取れた回に船名なしの行は消える。予備ルートの行は船名が分からないので、臨時便と同じ船か決められない。抑えると同じ港・同じ日を出る別の船の行まで消える（FR-015）
- **臨時便の詳細ページが取れない（一覧に臨時便の印がある）**：臨時便は寄港する港が詳細ページでしか分からないので、予備ルート（便全体の状態を全港に当てはめる）では行を作らない。前回作った行は残す。警告を出す
- **一覧に臨時便の印が無く、詳細ページが取れない**（一覧のクラスが読めても読めなくても）：臨時便か定期便か分からない。航路単位は書かないが、その日・その方向を「便なし」にもしない（FR-008）。港別は今までどおり予備ルートの行を作る。臨時便だった場合、その行は次に詳細ページが取れた回に消える（FR-011）
- **臨時便が寄らなくなった港**（前の回は寄る予定で行を作り、次の回に「寄港しません」になった）：その港の臨時便の行を消す（FR-011）
- **臨時便の港に、知らないクラスが付いている**：今までどおりその港は「不明」の行にする（読み飛ばすと前回の状態が残る）
- **臨時便の印が一覧にだけある・詳細ページにだけある**：どちらか一方に臨時便の印（`temporary`、または見出しの【臨時便…】）があれば臨時便として扱う
- **方向が見出しの港から分からない**（名瀬発など）：一覧の上り・下りの欄、または「〜向け」の行き先で方向を決める。どちらでも分からなければ今までどおり読み飛ばして警告を出す
- **定期便の行を臨時便が置き換えた後、一覧から臨時便が消える**：臨時便が出港済みなら、次の実行で定期便（欠航）を読んでも臨時便の行を上書きしない（US1 の 5）。まだ出港していなければ、取りやめとみて定期便の欠航に戻す（US1 の 6）。同じキーの定期便の行が無い臨時便の行（9/6 のクロスの鹿児島など）は、今のマリックスラインの行と同じく残る（`test_rows_are_kept_after_voyage_leaves_list`）
- **臨時便の出港日がずれる**（遅延で前の日付の行が残る）：今の定期便と同じく、同じ便の詳細ページの新しい情報で置き換え、古い日付の行を消す（#28 の扱い）。古い日付に同じキーの定期便の行（欠航など）があれば、その行は定期便の行に戻る（FR-007・FR-011）
- **年をまたぐ臨時便**：今の定期便と同じく、始発日の年で補う
- **9/6 のように、定期便と臨時便が別の船**：ぶつからないので、両方の行をそれぞれ作る

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: マリックスラインの一覧・詳細ページで、公式が臨時便の印を付けた便（一覧の便、または詳細ページの見出しの【臨時便…】・港の `temporary`）を臨時便として見分けなければならない
- **FR-002**: 臨時便の詳細ページで臨時便の印が付いた港の状態は、「臨時便」としなければならない。12 の「臨時便」と同じ状態を使い、港別の行だけで使う
- **FR-003**: 臨時便の詳細ページで「寄港しません」の港には、臨時便からの行（「抜港」の行も）を作ってはならない。その港の時刻も使ってはならない。同じキーの定期便の行があれば、それを残す（12-marue-extra-voyages の FR-006 と同じ）
- **FR-004**: 臨時便の行の出港予定・到着予定・船名・詳細は、今の定期便の行と同じく詳細ページから決めなければならない。詳細には公式の説明（見出しの h2・h4）を入れる
- **FR-005**: 同じ航路・港・出港日・船の行が、定期便と臨時便の両方から来るときは、定期便のその港の状態が欠航・運休・抜港・不明なら臨時便の行を残さなければならない。一覧の並び順で結果が変わってはならない
- **FR-006**: FR-005 で定期便のその港が走る状態（通常運航・条件付・航行経路変更など）なら、定期便の行を残し、詳細に臨時便の出港時刻を足して警告を出さなければならない
- **FR-007**: 前の実行で臨時便から書いた行（状態「臨時便」）は、次の実行で同じキーの定期便の行（欠航・運休・抜港・不明）が来ても、次のどちらかなら上書きしてはならない：その臨時便が今回の一覧にあるのに詳細ページを読めていない、またはその行の出港予定時刻を過ぎている（出港済み）。どちらでもなければ（一覧から消えた未出港の臨時便・出港日がずれた臨時便）、定期便の行を書く。定期便のその港が走る状態（FR-006）なら、いつでも定期便の行を書く
- **FR-008**: 航路単位（航路×日付）の状態は、定期便だけから決めなければならない。臨時便は航路単位に書かない。その方向・その日に臨時便しか無ければ、今までどおり定期便が無いものとして扱う（今日なら「便なし」）。一覧に臨時便の印が無く、詳細ページが取れない便は、臨時便かどうか分からないので航路単位に書かない。ただし、その方向・その日に便が無いもの（「便なし」）としても扱ってはならない
- **FR-009**: 便の方向は、始発港の名前のほか、一覧の上り・下りの欄、または行き先（「〜向け」）からも決めなければならない。名瀬発・鹿児島行きの便は上りとする
- **FR-010**: 一覧に臨時便の印がある便の詳細ページが取れないときは、予備ルートの行を作ってはならない。前回の行は残し、警告を出す
- **FR-011**: 臨時便の詳細ページを読めた回は、その臨時便の詳細ページから書いた行のうち、今回書かなかった行（出港日がずれた古い日付の行・寄らなくなった港の行・前の回に予備ルートで作った船名なしの行）を消さなければならない。消すのはその臨時便の詳細ページから書いた行だけとする
- **FR-012**: 港別ページ・会社詳細ページ・トップの会社カード（「◆ 臨時便 … 発」）・異常の要約・通知メールは、12 で作った「臨時便」の表示をそのまま使う。マリックスラインのための表示の変更はしない（FR-014 を除く）
- **FR-013**: 臨時便が無い日の、定期便の行・航路単位の結果は今と同じでなければならない。マルエーフェリー・奄美海運のスクレイパーの扱いは変えない
- **FR-014**: トップの会社カードで、航路単位が「便なし」で、今日その方向に「臨時便」の行が1つ以上あり、ほかに今日その方向を出る臨時便以外の行（始発港の行も含む）が無い航路は、バッジを「臨時便」にしなければならない（始発港を出る臨時便も含む）。会社を問わない（マルエーフェリーにも効く）。臨時便以外の行がある日は、今までどおりそちらでバッジを決める（12 の FR-016）
- **FR-015**: 定期便の詳細ページが取れないときの予備ルートの行（船名なし）は、臨時便の行と同じ航路・港・出港日でも、今までどおり作らなければならない（臨時便の行を理由に、抑えたり消したりしない）

### Key Entities

- **臨時便（マリックスライン）**: 公式の一覧・詳細ページに、定期便と同じ形で出る便。臨時便の印があり、寄港する港・時刻は詳細ページにだけある。欠航した定期便と同じ船・同じ時刻で出ることがある
- **港別の行**（既存）: 航路・港・出港日・船ごとの状態。臨時便が書いた行は、状態「臨時便」で見分ける（前の回の行を守るとき。FR-007）。どの便の詳細ページから書いたか（出どころ）も持つ

## Success Criteria *(mandatory)*

- **SC-002**: 2026-09-06 の臨時便の詳細ページで、鹿児島（9/6 09:00）の行が「臨時便」になり、寄港しない5港の臨時便の行は0行。定期便（プラス）の行は今と同じ
- **SC-003**: 2026-09-27 の臨時便の詳細ページで、上りの名瀬（9/27 05:50）の行が「臨時便」になる。8/25 の行は0行
- **SC-004**: 9/6・9/7 の一覧で、並び順に関係なく、航路単位が 9/6 下り「条件付運航」、9/7 上り「欠航」になる。「不明」は0件
- **SC-005**: 9/7 にトップを見ると、上りに「欠航」と「◆ 臨時便 那覇 07:00発」が両方出る。通知メールに、クロスの那覇・名瀬の「臨時便」の行が載る
- **SC-006**: 今のマリックスラインのテスト・保存ページ（臨時便の無いもの）で、定期便の行・航路単位の結果が今と同じ
- **SC-007**: 8/27 の臨時便（鹿児島 10:00 発、その日の下りの定期便なし）で、トップの下りのバッジが「臨時便」になる。「便なし」は0件

- **SC-009**: 一覧に臨時便の印が無く詳細ページが取れない便が、その方向の今日の唯一の便のとき、航路単位は書かれない（「不明」も「便なし」も書かない）。次に詳細ページが取れた回に、定期便なら航路単位が書かれる

## Assumptions

- 一覧の臨時便の便のクラスにも `temporary` が付く（一覧の CSS に `.temporary` の並び順の指定がある）。実物の一覧の HTML は未確認なので、詳細ページの見出し（【臨時便…】）・港のクラスでも臨時便と見分けられるようにする
- 一覧の臨時便も、定期便と同じく上り・下りの欄に分かれて出る。見出し（info2）の書き方は、定期便と同じ「YYYY年M月D日 〇〇港発 … 〇〇港 向け」と考える
- 臨時便の詳細ページの形（`div.service > div.single`、港名・入出港時刻・クラス）は定期便と同じ（2026-08〜09 の4例で確認）
- 臨時便は、欠航した定期便の代わりに出る。同じ船・同じ時刻で出ることが多い（9/7）。定期便が走る日に同じ船で臨時便が出ることは、公式の記録では無い
- 公式は、過ぎた臨時便を「過去の運航状況」に出さない。一覧から消えた臨時便は、出港済みなら行を残す。まだ出港していなければ、同じキーの定期便の行があるときだけ、そちらに戻す（FR-007）
- 臨時便が寄港しない港（`no_status`）は、12 と同じく「その港には臨時便が無い」とみなす（Clarifications）。寄港しない港の時刻は当てにならない（9/27 の便に 8/25 が残る）ので、その意味でも行を作らないほうが安全
- DB のスキーマは変えない（「臨時便」の状態は 12 で追加済み）

## Out of Scope

- 臨時便の取りやめ（出港前に一覧・詳細ページから消える）を見つけて、同じキーの定期便の行が無い臨時便の行を消すこと。公式で起きた例が無い。必要になったら別の機能にする（同じキーの定期便の行がある港は、FR-007 で定期便の行に戻る）
- マルエーフェリー・奄美海運の臨時便の扱いの変更
- 臨時便のための画面・通知メールの文言の変更（12 の表示をそのまま使う。トップのバッジ（FR-014）だけ変える）
