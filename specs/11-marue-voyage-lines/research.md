# Research: 先の便にも公式の便ごとの状態を出す

**Date**: 2026-10-26 | **Spec**: [spec.md](spec.md)

## R1. 便の行と便の照合を1か所にまとめる

**Decision**: `MarueFerry._voyage_line(ship, route_id, origin_date, arrival_date) -> VoyageStatus | None` を作り、今の便・先の便・航路単位の3か所から使う。

- 方向は航路から決める（下り＝鹿児島発、上り＝那覇発。今の `_route_directions()`）
- まず `departure_date == origin_date` の行を探す。無ければ `origin_date <= departure_date <= arrival_date` の行を探す（FR-012）。どちらも最初に見つかった行
- `origin_date` ＝ 下船日 −（終点の day_offset − 始発港の day_offset）。今の `_for_current_voyage()` の計算をそのまま使う

**Rationale**: 今は `_match_voyage()` が出港日の一致だけを見ていて、今の便と航路単位でしか使っていない。先の便も同じ決まりで照合しないと、同じ行が便によって合ったり合わなかったりする。

**Alternatives considered**:
- 範囲だけで照合する：10/27 上り（10/27〜10/28）に「10/28 那覇港発上り便…臨時便運航」も入る。出港日が一致する行を先に見れば、10/27 の「欠航」の行が選ばれる
- 途中の港の行を、港名から日のずれを出して直す：港名の読み取りが要る。範囲で十分

**残るリスク**: 同じ方向で、出港日の一致する行が無い便に、隣の臨時便の行が範囲で当たることがある。同じ船の同じ方向の便は4日くらいあくので、範囲（1〜2日）に入るのは臨時便のように予定外の便だけ。抜粋に元の便の行（欠航）が無いときに限られるので、受け入れる。

## R2. 今の便の判定（FR-011）

**Decision**: `_for_voyage()` を次のように変える。

| 抜粋の便の行 | 今の便に合う行 | 結果 |
|---|---|---|
| 0行 | — | 船のタグ（今まで） |
| 1行 | 合う | 船のタグ（今まで。行が1つならタグもその便のもの） |
| 2行以上 | 合う | その行の状態（今まで） |
| 1行以上 | 合わない | **operating**（今は船のタグ）。`conditional`・`schedule_changed` は False |

合わないときの `voyage_not_in_excerpt` の警告は残す（運用で気づけるように）。「通常運航にした」ことが分かるように `assumed=operating` を付ける。

**Rationale**: spec の Clarifications。合わないのに船のタグを使うと、10/28 08:30 以降に 10/29 鹿児島発（定期便）が「欠航」になる。

**影響する既存テスト**: `test_voyage_not_in_excerpt_keeps_ship_status` は今の便が出港済み（10/20 07:00 発、11:39 に実行）なので、R7 により結果は `cancelled` のまま。名前だけ `test_departed_voyage_not_in_excerpt_keeps_ship_status` に変える。出港前で `operating` になるケースは新しいテスト（T014）で見る。

## R3. 先の便（FR-001〜004）

**Decision**: `parse_departures()` で、今の便でないマルエーの行に `_future_voyage_status(ship_name, ships, route_id, row)` を使う。

- 船ブロックが無い・便の行が0 → `(None, None)`（運航予定。今まで）
- `_voyage_line()` が None → `(None, None)`
- 合う行がある → 行が1つならタグのステータス、2つ以上なら行のステータス（R2 と同じ決まり）。詳細は抜粋（通常運航なら None）
- 港別情報（`_ship_notices`）は使わない（FR-004）。抜港の行（`_skipped_on_current_voyage`）も今の便だけ

spec の Edge Cases の「便の行が1つだけ」は、先の便も今の便と同じく「合えばタグ」とする（行が1つのときは、タグとその行は同じ便を指す）。

**Rationale**: 今の便と同じ関数で決めれば、今の便が着いて先の便が今の便になったときに、表示が変わらない。

## R4. 「臨時便運航」を読む（FR-005・FR-006）

**Decision**: `_parse_status_text()` で「欠航」の後に `"臨時" in text` → `operating` を足す。

- タグ「欠航」「臨時便運航」→ `_classify()` は一番重いものなので `cancelled`（FR-006）
- 便の行「…臨時便運航」→ `operating`

**Alternatives considered**: 新しいステータス（臨時便）を足す：画面・通知・PHP の enum まで変わる。臨時便の行を作る機能（範囲外）で決めればいい。

## R5. 2日先以降の検索（FR-010）

**Decision**: `fetch()` の順番を「鹿児島航路ページ → 便検索 → 船別詳細ページ」に入れ替え、便検索の前に便の行を読めるようにする。2日先以降のキーは、`_needs_far_search()` が False でも、次の条件なら検索する。

- いずれかの船の便の行 `(departure_date, direction)` について、その方向の航路の終点以外の各停泊港の日付 `departure_date + (stop.day_offset − stops[0].day_offset)` がそのキーの日付と同じ

範囲で照合する行（途中の港から書いた行）も拾えるように、行の日付と翌日（day_offset のずれの最大）の両方を始発の出港日とみなして候補にする。検索が少し増えるだけで、外れても害は無い。

**Rationale**: 便の行が無い日付は今までどおり6時間おき（FR-010 の後半）。便の行は1隻あたり数行なので、増えても1回の実行で十数回まで。

**Alternatives considered**:
- 検索せずに、前回の検索結果（DB の行）に状態だけ書き直す：`replace_scope` で港×日付を丸ごと置き換える作りと合わない。行を作り直す経路が増える
- 2日先以降を毎回検索：spec の Q1 で却下

**影響**: 鹿児島航路ページの取得が失敗すると、今は検索の後で例外になる。順番を変えると検索の前に例外になるので、無駄な検索が減る。`raw_html_hash` に使う文字列は変えない。

## R6. 航路単位（operation_statuses）

**Decision**: `_route_status()` で `_for_voyage(ship, route.id, valid_date, arrival_date)` を使う。`arrival_date` は今日の始発港の検索結果の1行目の下船日。R2 の表どおり、行が読めて合わなければ operating。

## R7. 範囲での照合と出港済みの今の便（今日の波之上で確かめた）

10/26 の波之上の今の便は 10/25 鹿児島発下り（欠航、10/26 19:00 着）。抜粋からこの便の行はもう消えていて、「10/26 鹿児島新港発下り便…臨時便運航」がある。R1・R2 のままだと次の2つが起きる。

1. 範囲（10/25〜10/26）に 10/26 の臨時便の行が入り、欠航の便が operating になる
2. 1 を防いでも、行が合わないので FR-011 で operating になる

和泊・与論・本部の 10/26 の行はまだ出港前なので、上書きされて「通常運航」と出る。

**Decision**:

- **範囲での照合は、途中の港から書いた行だけ**。行の「…発」の前の港名が始発港（鹿児島・那覇。「鹿児島新港」「那覇港」を含む）なら、その行の日付は始発港の出港日そのものなので、出港日の一致でしか照合しない。`VoyageStatus` に `from_origin: bool` を足す（`_VOYAGE_LINE` の日付と方向の間の文字列に「鹿児島」「那覇」があるか）
- **FR-011（合わなければ operating）は、出港前の今の便だけ**。出港済みの今の便は、前回までに記録したその便のステータス（DB。同じ船・航路で下船日時の差が24時間未満の行の status のうち、NULL・skipped を除いて一番重いもの）を使う。記録が無ければ船のタグ。公式は過ぎた便の行を消すので、出港済みの便に行が無いのは「変更なし」の証拠にならない。かといって船のタグに戻すと、出港前に operating と判定した便が出港した瞬間に、古いタグ（欠航）で上書きされる
- **出港済み** ＝ その便の始発港の出港日が今日より前、またはこの回の検索結果にあるその便の行のうち一番早い乗船日時が今以前

**結果（2026-10-26 の保存ページ）**:

| 便 | 今の便？ | 照合 | 結果 |
|---|---|---|---|
| 10/25 鹿児島発下り（10/26 19:00 着） | ○（出港済み） | 合わない | 前回の記録 cancelled → cancelled（今と同じ） |
| 10/27 那覇発上り | × | 出港日が一致 | cancelled（SC-001） |
| 10/29 鹿児島発下り（10/28 の時点） | ○（出港前） | 合わない | operating（SC-006） |
| 10/29 鹿児島発下り（10/29 20:00 の時点） | ○（出港済み） | 合わない | 前回の記録 operating → operating |
