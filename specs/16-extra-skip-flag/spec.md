# Feature Specification: 臨時便の抜港をスクレイパーが行のフラグで持つ

**Feature Branch**: `16-extra-skip-flag`
**Created**: 2026-10-27
**Status**: Draft
**Input**: User description: "Issue #96: 臨時便の抜港をスクレイパーが行のフラグで持つ。15-extra-voyage-badge（PR #95）の「・抜港あり」は、ボードの行から「同じ船の寄る行が無い港」を逆算している（PortBoard::extraSkipsPortsOf）。抜港かどうかはスクレイパーがもう知っている（マリックス: _SKIPPED_PORT_CLASS = no_status、マルエー: 臨時便の stops と寄港順の差・voyage.skip_note）のに捨ててから組み立て直すため割り切りが多い。変更: スクレイパーが臨時便の行に抜港のフラグ（departure_statuses の列）を書き、Web はそれを読むだけにする。DB の列追加（マイグレーション）、両スクレイパーの取り込み、既存行は次のスクレイプで書き直す。"

## 概要

15-extra-voyage-badge で、トップの会社カードの臨時便の1行に「・抜港あり」を出した（15 の FR-004）。今は Web が、港別ボードの行から「同じ船の寄る行が無い港」を逆算して決めている。

ところが、抜港かどうかはスクレイパーが取り込むときにもう分かっている。

- マルエーフェリー：船の詳細ページの【臨時便】に、寄る港が順に並ぶ。航路の寄港順にあって並びに無い港が抜港（「※ …寄港いたしません。」の文もある）
- マリックスライン：便の詳細ページで、臨時便が寄らない港は「寄港しません」（`no_status`）と出る

スクレイパーは寄らない港の行を作らない（12 の FR-006・13 の FR-003）ので、この情報は DB に残らない。Web は残った行から組み立て直すしかなく、次の割り切り・取りこぼしがある（15 の research R3）。

| 割り切り・取りこぼし | 起きること |
|---|---|
| 船名＋到着予定で行を1回の運航にまとめ直す | 到着予定が無い臨時便は判定できない（「抜港あり」を出さない） |
| 同じ船が同じ日に別の運航でその港に寄ると寄港に数える | 抜港を見落とす |
| 港の並びを日付をまたいで同じとみなす | 並びが日によって変わると誤判定する |
| 便検索の no_service の行に隠れた寄港を、行に残した船名で拾う | 画面に出さない値をボードに持ち回る |
| ボードの行は出発港だけ | 終点の1個前の港の抜港を見落とす（運航の最後が「最後の出発港」になる） |

この機能で、スクレイパーが臨時便の行ごとに「この港を出たあと、運航の最後の港までに寄らない港があるか」を書き、Web はそれを読むだけにする。

### 例：2026-10-27 のマルエーフェリー下り（15 の例）

フェリー波之上の臨時便：鹿児島 10/26 発 → 名瀬 10/27 03:50 発 → 本部 10/27 12:00 発 → 那覇 13:50 着。亀徳・和泊・与論には寄らない。

| 港 | 出港 | この港を出たあとに抜港 |
|---|---|---|
| 鹿児島 | 10/26 | あり（亀徳・和泊・与論） |
| 名瀬 | 10/27 03:50 | あり（亀徳・和泊・与論） |
| 本部 | 10/27 12:00 | なし（次は終点の那覇） |

10/27 の会社カード：今日の臨時便の行（名瀬・本部）のどれかが「あり」なので「◆ 臨時便 名瀬 03:50発・抜港あり」（15 と同じ）。

### 例：終点の1個前の港を抜く臨時便（今は見落とす）

上りの臨時便：那覇 → 本部 → 与論 → 和泊 → 亀徳 → 鹿児島（名瀬に寄らない）。今の逆算では、ボードの行の最後が亀徳になり、名瀬が判定の範囲に入らないので「抜港あり」が出ない。この機能では、那覇〜亀徳の行が「あり」になり、「・抜港あり」が出る。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 臨時便の抜港を取りこぼさずに知らせる (Priority: P1)

トップを見た利用者が、今日その方向の臨時便が自分の港に寄らないかもしれないことに、会社カードの「・抜港あり」で気づける。終点の1個前の港を抜く臨時便、到着予定が分からない臨時便でも出る。

**Why this priority**: 抜港は寄らない港の利用者には欠航と同じ意味を持つ。15 で出した「・抜港あり」が出ない便があると、カードを見て安心して港へ行ってしまう。

**Independent Test**: 終点の1個前の港（上りの名瀬）を抜く臨時便のデータで、スクレイパーを流してからトップを表示し、臨時便の1行に「・抜港あり」が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 今日の下りに、亀徳・和泊・与論を抜く臨時便の行（名瀬・本部）がある（2026-10-27 の形）, **When** トップを見る, **Then** 「◆ 臨時便 名瀬 03:50発・抜港あり」
2. **Given** 今日の上りに、終点の1個前の名瀬を抜く臨時便の行がある, **When** トップを見る, **Then** 臨時便の1行に「・抜港あり」が出る
3. **Given** 今日の上りに、那覇を出て本部・与論・和泊・亀徳を抜き名瀬に寄る臨時便がある（2026-09-07 マリックス上りの形）, **When** トップを見る, **Then** 「◆ 臨時便 那覇 07:00発・抜港あり」
4. **Given** 臨時便が定期便の寄港地すべてに寄る（2026-09-27 マリックス上りの名瀬→鹿児島など）, **When** トップを見る, **Then** 「・抜港あり」を出さない
5. **Given** 臨時便の到着予定が分からない（詳細ページに終点の入港が無い）が、途中の港を抜くことは分かる, **When** トップを見る, **Then** 「・抜港あり」が出る
6. **Given** 臨時便がある港で便検索の行とぶつかり、その港に臨時便の行が無い（12 の「臨時便 HH:MM発あり」）, **When** トップを見る, **Then** その港は抜港に数えない（臨時便はその港に寄る）

---

### User Story 2 - 抜港の判断をスクレイパーの1か所にまとめる (Priority: P2)

開発者が、抜港の判断を会社ごとのスクレイパーで公式の書き方どおりに行い、Web は行のフラグを読むだけにできる。Web から逆算の処理と、そのためだけに持ち回っていた値を消す。

**Why this priority**: 利用者の見え方は US1 で決まる。逆算が残ると、同じことを2か所で判断して食い違う。割り切りのテストも負債になる。

**Independent Test**: Web のテストで、臨時便の行のフラグだけを変えて「・抜港あり」が出る・出ないが切り替わることを確かめる。逆算の処理と、便検索の no_service の船名を持ち回る値がコードから無くなっている。

**Acceptance Scenarios**:

1. **Given** 今日その方向の臨時便の行のどれかにフラグがある, **When** トップを見る, **Then** 「・抜港あり」が出る
2. **Given** 今日その方向の臨時便の行のどれにもフラグが無い, **When** トップを見る, **Then** 「・抜港あり」を出さない（ほかの日・ほかの行の並びに関係なく）
3. **Given** フラグがある行の状態が、抜粋で欠航・運休・条件付になった（12 の R4）, **When** トップを見る, **Then** その行は臨時便として数えない（今の1行と同じ）

---

### Edge Cases

- **前日に始発港を出た臨時便**：今日の行のフラグだけを見る。今日より前に通った港の抜港は数えない（15 と同じ。今日の最初の港から先を見る）
- **今日出て明日に次の港を出る臨時便**：今日の行のフラグに、明日以降の港の抜港も入る（運航の最後の港まで見る）
- **臨時便が始発港より後から出る・終点の手前で終わる**：運航の最初の港より前、最後の港より後の港は抜港に数えない（15 の Edge Cases と同じ）。マリックスで臨時便が寄らない港が運航の前後にあっても、抜港にしない
- **詳細ページに航路の港が出てこない**（マリックスの `detail_stop_missing` の形）：寄らないと書かれていない港は、抜港に数えない（分からないときは「抜港あり」と言わない側に倒す）
- **同じ日・同じ方向に臨時便が2つ以上**：どれか1つでもフラグがあれば「抜港あり」（15 と同じ）
- **定期便の行**：フラグは持たない（定期便の抜港は今までどおり状態「抜港」の行で出す）
- **出港済みで書き直さない行**（マルエーの臨時便の行は出港後に確定する）：この機能を入れる前に出港した行はフラグが無いまま。入れた日のその行だけ「・抜港あり」が出ないことがある（次の日からは起きない）
- **公式が臨時便の寄港地を変えた**：次のスクレイプで、残る行のフラグも書き直す（寄らなくなった港の行は今までどおり消える）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: スクレイパーは、臨時便の港の行ごとに、「その港を出たあと、その臨時便の最後の港までに、航路の寄港順にある港のうち臨時便が寄らない港があるか」を記録しなければならない。最後の港は、臨時便が寄る港のうち寄港順で最後のもの（終点まで行く便なら終点）
- **FR-002**: マルエーフェリーは、船の詳細ページの【臨時便】に並ぶ港と航路の寄港順から FR-001 を決めなければならない（並びに無い港を寄らない港とする）
- **FR-003**: マリックスラインは、便の詳細ページで寄らない（「寄港しません」）と書かれた港から FR-001 を決めなければならない。詳細ページに出てこない港は寄らない港に数えない
- **FR-004**: 臨時便の行が便検索・定期便の行とぶつかって作られない港（12 の R7・13 の R4）も、臨時便が寄る港として扱わなければならない（抜港にしない）
- **FR-005**: 定期便の行は、FR-001 の記録を持ってはならない（「なし」のまま）
- **FR-006**: トップの会社カードの「・抜港あり」は、今日その方向の「臨時便」の行のうち1つでも FR-001 が「あり」なら出し、そうでなければ出してはならない。ボードのほかの行・ほかの日からは判断しない
- **FR-007**: 「・抜港あり」の文言・位置・臨時便の1行の時刻（いちばん早い臨時便）は、15 のとおりでなければならない
- **FR-008**: Web から、行の並びから抜港を逆算する処理と、そのためだけに持っていた値（便検索の no_service の船名など）を無くさなければならない
- **FR-009**: 臨時便が無い日の表示、会社詳細ページ・港別ページの行・通知メールは、今と変えてはならない
- **FR-010**: 既にある行は、FR-001 を「なし」として扱い、次のスクレイプで書き直さなければならない。書き直しのために、臨時便でない行の内容を変えたことにしてはならない（更新時刻を無駄に進めない）
- **FR-011**: 15 の契約（`contracts/ui-status.md`）・research R3 のうち、この機能で変える決まりは、この機能の契約で上書きしたことが分かるようにしなければならない

### Key Entities

- **臨時便の行**（既存）：港別の行のうち臨時便が書いたもの。この機能で「この港を出たあとに抜港があるか」を足す
- **航路の寄港順**（既存）：航路ごとの港の並び。抜港かどうかの判断に使う

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 2026-10-27 下り・2026-09-07 上りの形で「・抜港あり」が出て、2026-09-27 上りの形で出ない（15 の SC-004 がそのまま通る）
- **SC-002**: 終点の1個前の港を抜く臨時便・到着予定が分からない臨時便で、「・抜港あり」が出る（今は出ない。テストで再現）
- **SC-003**: 臨時便が無い日のトップ・会社詳細・港別・通知メールの表示が、変更前と1文字も変わらない（既存のテストがそのまま通る）
- **SC-004**: 機能を入れたあとの最初のスクレイプで、臨時便でない行の更新時刻が進まない

## Assumptions

- 「抜港あり」を行ごと（その港を出たあと）に持つ。運航ごとに持つと、前日に通った港の抜港で今日「抜港あり」と出てしまう（15 は今日の最初の港から見ていた。それに合わせる）
- 臨時便の運航の最初と最後の港は、スクレイパーが詳細ページから分かる（マルエー：【臨時便】の最初と最後の港、マリックス：寄る港の最初と最後）
- 抜粋で欠航・運休・条件付になった臨時便の行（12 の R4）にもフラグは書くが、状態が「臨時便」でないので「・抜港あり」の判断には入らない
- どの港を抜くか（港名）は記録しない。カードには出さない（15 の Out of Scope）。会社詳細ページの行の詳細（マルエーの「※ …寄港いたしません。」）は今までどおり
- 本番で列を足したあと、スクレイパーの次の定期実行で書き直される。手で全部の行を書き直す作業は要らない

## Out of Scope

- 会社詳細ページ・港別ページに、臨時便の抜港を出すこと
- 臨時便が寄らない港に「抜港」の行を作ること（12 の FR-006・13 の FR-003 のまま）
- 定期便の抜港の扱い（今の状態「抜港」の行のまま）
- 臨時便を航路単位に書くこと（13 の FR-008 のまま）
