# Feature Specification: 運航情報Webサイト

**Feature**: `website`
**Created**: 2026-03-07
**Status**: Draft

---

## User Scenarios & Testing

### User Story 1 - 今日の運航状況をトップページで確認 (Priority: P1)

利用者がトップページにアクセスし、本日の全社・全航路の運航状況を一覧で確認できる。

**Why this priority**: サイトの起点となる最重要ページ。これだけで最小限の価値を提供できる。

**Independent Test**: `http://localhost:8080/` にアクセスして、両社の運航状況が表示されること。

**画面イメージ**:
```
┌─────────────────────────────────────────────┐
│ ShipInfo - フェリー運航情報                   │
├─────────────────────────────────────────────┤
│ 2026年3月7日（金）の運航状況                  │
│                                             │
│ [マルエーフェリー]                           │
│  鹿児島〜名瀬〜亀徳  ● 条件付運航            │
│  鹿児島〜名瀬       ✓ 通常運航              │
│                                             │
│ [マリックスライン]                           │
│  鹿児島〜那覇       ✗ 欠航（台風のため）     │
└─────────────────────────────────────────────┘
```

**Acceptance Scenarios**:

1. **Given** DBに本日の運航状況データがある場合、**When** トップページにアクセス、**Then** 全社・全航路の運航状況が表示される
2. **Given** DBに本日データがない場合（スクレイピング未実施）、**When** トップページにアクセス、**Then** 「情報を取得中です」などのメッセージが表示される
3. **Given** 欠航の便がある場合、**When** トップページにアクセス、**Then** 欠航が視覚的に強調表示される（赤色等）

---

### User Story 2 - 会社別ページで詳細を確認 (Priority: P2)

利用者が会社別ページにアクセスし、特定のフェリー会社の運航状況（本日 + 直近数日）を確認できる。

**Why this priority**: 特定の会社の便を使う利用者が詳細を確認できる。

**Independent Test**: `http://localhost:8080/company/{id}` にアクセスして、その会社の運航状況一覧が表示されること。

**URL設計**: `/company/{companyId}`

**画面イメージ**:
```
┌─────────────────────────────────────────────┐
│ < トップへ戻る                               │
│ マルエーフェリー 運航状況                    │
├─────────────────────────────────────────────┤
│ 3月7日（金）                                 │
│  鹿児島〜名瀬〜亀徳  ● 条件付運航            │
│    └ 理由: 荒天のため亀徳寄港を中止          │
│  鹿児島〜名瀬       ✓ 通常運航              │
│                                             │
│ 3月8日（土）                                 │
│  鹿児島〜名瀬〜亀徳  ✗ 欠航                 │
│    └ 理由: 台風接近のため                    │
└─────────────────────────────────────────────┘
```

**Acceptance Scenarios**:

1. **Given** 存在する会社IDでアクセス、**When** 会社別ページを表示、**Then** 直近3日分の運航状況が日付順で表示される
2. **Given** 存在しない会社IDでアクセス、**When** 会社別ページを表示、**Then** 404ページが表示される
3. **Given** 欠航の便、**When** 会社別ページを表示、**Then** `status_detail`（理由）が表示される

---

### User Story 3 - 航路別詳細ページ（将来対応・会社ごとに出す・出さないを選択可能） (Priority: P3)

特定の航路の運航状況履歴・詳細を確認できる。会社の設定で表示・非表示を切り替えられる。

**Why this priority**: 将来の拡張。MVP後に検討。

**Independent Test**: `http://localhost:8080/route/{id}` にアクセスして航路別の状況が表示されること。

**URL設計**: `/route/{routeId}`

**設計方針**:
- `ferry_companies` テーブルに `show_route_detail` boolean カラムを追加して制御
- 非表示設定の場合は会社別ページにリンクを表示しない

**Acceptance Scenarios**:

1. **Given** `show_route_detail = true` の会社の航路、**When** 航路別ページにアクセス、**Then** 過去7日分の運航状況が表示される
2. **Given** `show_route_detail = false` の会社、**When** 会社別ページを閲覧、**Then** 航路詳細へのリンクが表示されない

---

### Edge Cases

- データが0件: 「現在情報がありません」を表示
- 文字化け対策: UTF-8を明示的に設定
- モバイル対応: レスポンシブデザイン（Bootstrap等のCSSフレームワーク使用）

---

## Requirements

### Functional Requirements

- **FR-001**: System MUST トップページ（`/`）で本日の全社・全航路の運航状況を表示すること
- **FR-002**: System MUST 会社別ページ（`/company/{id}`）で直近3日分の運航状況を表示すること
- **FR-003**: System MUST 各ページにフェリー会社へのリンクを設けること
- **FR-004**: System MUST 運航状況をステータス別に視覚的に区別すること（色・アイコン）
- **FR-005**: System MUST 存在しないIDへのアクセスに404を返すこと
- **FR-006**: System MUST モバイルブラウザで閲覧できること（レスポンシブ）

### ステータスの表示定義

| DB値 | 表示ラベル | 色 |
|---|---|---|
| `operating` | 通常運航 | 緑 |
| `delayed` | 条件付・遅延 | 黄 |
| `cancelled` | 欠航 | 赤 |
| `suspended` | 運休 | グレー |
| `unknown` | 情報なし | グレー |

### 技術要件

- **Controller**: `App\Controller\StatusController`
- **テンプレート**: `templates/status/`
- **CSSフレームワーク**: Bootstrap 5（CDN経由）
- **DBアクセス**: `OperationStatusRepository` 経由（生SQLは使わない）

---

## Success Criteria

- **SC-001**: `http://localhost:8080/` でトップページが表示される
- **SC-002**: 欠航便が赤、通常運航が緑で表示され、視覚的に区別できる
- **SC-003**: スマートフォンのブラウザで横スクロールなしに閲覧できる
- **SC-004**: DBに当日データがない状態でも500エラーにならない
