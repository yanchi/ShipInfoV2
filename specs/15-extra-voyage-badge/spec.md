# Feature Specification: 臨時便がある日の会社カードのバッジを「スケジュール変更」にする

**Feature Branch**: `15-extra-voyage-badge`
**Created**: 2026-10-27
**Status**: Draft
**Input**: User description: "トップの会社カードで、今日その方向に臨時便がある航路の表示を直す。今は航路のバッジが始発港の便だけで決まり、始発港の便が通常運航・運航予定なら「✓ 通常運航」が出て、臨時便は下の青い1行（◆ 臨時便 名瀬 03:50発）だけになる。例: 2026-10-27 マルエー下りは鹿児島 18:00 あけぼのが運航予定、前日の下り便が「臨時便運航」になり波之上が名瀬 03:50・本部 12:00 発（亀徳・和泊・与論は抜港）。緑の「通常運航」で何もないように読めてしまう。変更: (1) 臨時便がある日は、始発港の便が通常運航・運航予定のとき航路のバッジを「▲ スケジュール変更」にする（欠航など重い状態はそのまま）。青い1行は残す。(2) 臨時便の1行に抜港があることも出す。(3) 通知メールの「通常運航（臨時便あり）」も同じ考え方に揃える。spec 12・13 の「臨時便は定期便の通常運航と混ざってもスケジュール変更にしない」という決定を変える。"

## 概要

トップの会社カードの航路のバッジは、今日その航路の始発港を出る便（航路単位）の状態で決まる。臨時便は航路単位に書かないので（13 の FR-008）、バッジには入らない。代わりにバッジの下に青い1行「◆ 臨時便 名瀬 03:50発」を出している（12 の FR-016）。

12・13 では「臨時便は下の1行で伝えるので、定期便の通常運航と混ざってもスケジュール変更にしない」と決めた。ところが実際の臨時便は、ダイヤが崩れた便の代わりに出ることが多い。時刻が定期便と違い、寄らない港もある。それでもバッジは緑の「✓ 通常運航」になり、パッと見で「この方向は何もない」と読めてしまう。

### 2026-10-27 のマルエーフェリー下り（本番の表示）

| 港 | 出港 | 船 | 状態 |
|---|---|---|---|
| 鹿児島 | 10/27 18:00 | フェリーあけぼの | 運航予定（定期便） |
| 名瀬 | 10/27 03:50 | フェリー波之上 | 臨時便（10/26 鹿児島発の下り便が「臨時便運航」になったもの） |
| 本部 | 10/27 12:00 | フェリー波之上 | 臨時便 |

亀徳・和泊・与論には波之上が寄らない（「※ 亀徳港(徳之島)、和泊港(沖永良部島)、与論港(与論島)には寄港いたしません。」）。

会社カードの表示は次のとおり。

```
鹿児島〜那覇（下り）                    ✓ 通常運航
◆ 臨時便 名瀬 03:50発
```

## Clarifications

### Session 2026-10-27

- Q: 臨時便が全部出港したあとのバッジは？ → A: その日はずっと「▲ スケジュール変更」。臨時便の1行（出港済みも出す）と合わせる。臨時便が出る日は前の便のダイヤが崩れていて、残りの定期便にも影響しうるため（FR-001）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 臨時便がある日は「通常運航」と出さない (Priority: P1)

トップを見た利用者が、今日その方向に臨時便があり、時刻や寄港地がいつもと違うことにすぐ気づける。始発港の定期便が通常どおりでも、バッジは緑の「通常運航」ではなく「▲ スケジュール変更」になる。

**Why this priority**: 「通常運航」と読んで公式を見ずに港へ行くと、時刻違い・抜港で船に乗れないことがある。いちばん害が大きい。

**Independent Test**: 2026-10-27 の下りのデータ（始発港は運航予定・途中の港に臨時便）でトップを表示し、下りのバッジが「▲ スケジュール変更」、その下に臨時便の1行が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 今日の下りの航路単位が通常運航で、今日下りの臨時便の行がある, **When** トップを見る, **Then** 下りのバッジは「▲ スケジュール変更」で、その下に「◆ 臨時便 名瀬 03:50発」の1行が出る
2. **Given** 航路単位が便なしで、途中の港を出る定期便がすべて運航予定、ほかに今日その方向の臨時便がある, **When** トップを見る, **Then** バッジは「▲ スケジュール変更」（「○ 運航予定」にしない）
3. **Given** 今日の上りの航路単位が欠航で、上りの臨時便がある（2026-09-07 マリックス上りの形）, **When** トップを見る, **Then** バッジは今までどおり「✗ 欠航」と注意書き、その下に臨時便の1行
4. **Given** 航路単位が条件付・遅延で臨時便がある（2026-09-06 マリックス下りの形）, **When** トップを見る, **Then** バッジは今までどおり「▲ 条件付・遅延」
5. **Given** その方向に臨時便以外の便が無い日（8/27 型・9/27 型）, **When** トップを見る, **Then** 今までどおり「◆ 臨時便」のバッジ（13 の FR-014）
6. **Given** 臨時便が無い日, **When** トップを見る, **Then** バッジは今と同じ

---

### User Story 2 - 臨時便の1行で抜港に気づける (Priority: P2)

臨時便が定期便の寄港地の一部に寄らないとき、会社カードの臨時便の1行に「抜港あり」が出る。利用者は自分の港に船が来ないかもしれないと気づき、会社詳細ページを見に行ける。

**Why this priority**: バッジ（US1）で「何か変わっている」までは伝わる。抜港は、寄らない港の利用者には欠航と同じ意味を持つので、カードの段階で知らせたい。

**Independent Test**: 2026-10-27 の下り（名瀬・本部に臨時便の行、亀徳・和泊・与論に行なし）でトップを表示し、1行が「◆ 臨時便 名瀬 03:50発・抜港あり」になることを確かめる。

**Acceptance Scenarios**:

1. **Given** 臨時便が名瀬・本部を出て、そのあいだの亀徳・和泊・与論に寄らない, **When** トップを見る, **Then** 臨時便の1行は「◆ 臨時便 名瀬 03:50発・抜港あり」
2. **Given** 臨時便が定期便の寄港地すべてに寄る（2026-09-27 マリックス上りの名瀬→鹿児島など、あいだに港が無い便も含む）, **When** トップを見る, **Then** 臨時便の1行は今までどおり「◆ 臨時便 名瀬 05:50発」（「抜港あり」を出さない）
3. **Given** 臨時便が那覇を出て、本部・与論・和泊・亀徳に寄らず名瀬に寄る（2026-09-07 マリックス上りの形）, **When** トップを見る, **Then** 「◆ 臨時便 那覇 07:00発・抜港あり」

---

### User Story 3 - 通知メールの状況も揃える (Priority: P3)

通知メールの受け手も、臨時便がある日を「通常運航」と読まない。航路単位が通常運航で、通常以外の港の行に臨時便が1つでもあれば、状況の頭は「スケジュール変更」になる。

航路単位が便なし・行なしの日は、途中の港の定期便が通常運航でもメールの文言は変えない（サイトは「▲ スケジュール変更」）。メールに載るのは通常以外の港の行だけで、途中の港の定期便が通常運航かはメールの組み立てでは分からない。どちらにしても「通常運航」とは書かず、港の行に「臨時便」が並ぶので読み違いは起きない（research R4）。

**Why this priority**: メールはもともと臨時便の港を全部並べているので、状況の文言が違っても読み違いは小さい。サイトと文言を揃えるため。

**Independent Test**: 航路単位が通常運航、港の行が臨時便だけのデータで `make notify-dry-run` を流し、状況が「スケジュール変更（臨時便あり）」になることを確かめる。

**Acceptance Scenarios**:

1. **Given** 航路×日付が通常運航で、通常以外の港の行がすべて臨時便, **When** 通知メールを作る, **Then** 状況は「スケジュール変更（臨時便あり）」
2. **Given** 航路×日付が便なし・行なしで、通常以外の港の行がすべて臨時便, **When** 通知メールを作る, **Then** 状況は今までどおり「臨時便あり」
3. **Given** 航路×日付が欠航などで臨時便の行もある, **When** 通知メールを作る, **Then** 状況は今までどおりその状態（「欠航」など）
4. **Given** 航路×日付が通常運航で、通常以外の港の行に臨時便とそれ以外（欠航など）が混ざる, **When** 通知メールを作る, **Then** 状況は「スケジュール変更（途中の港に変更あり）」
5. **Given** 航路×日付が通常運航で、通常以外の港の行に臨時便が無い（欠航などだけ）, **When** 通知メールを作る, **Then** 状況は今までどおり「通常運航（途中の港に変更あり）」
6. **Given** 航路×日付が便なし・行なしで、通常以外の港の行に臨時便とそれ以外が混ざる, **When** 通知メールを作る, **Then** 状況は今までどおり「情報なし（途中の港に変更あり）」

---

### Edge Cases

- **臨時便が出港済み**：その日の臨時便が全部出港済みでも、今日その方向に臨時便があったことに変わりはない。バッジは「▲ スケジュール変更」のまま（臨時便の1行も出港済みで出し続けている。12 の FR-016）
- **臨時便の行が抜粋で欠航・運休・条件付**（12 の R4）：その行の状態は「臨時便」ではないので、臨時便としては数えない（今の1行と同じ）。欠航などとして今までどおり扱う
- **航路単位が不明・情報なし**：今までどおりの表示にする（不明より「スケジュール変更」が正しいとは言えない）
- **航路単位が便なしで、途中の港に欠航などと通常運航が混ざる**：今までどおり「▲ スケジュール変更」（変わらない）
- **臨時便が日をまたぐ**：抜港は、その臨時便（同じ船・同じ方向の1回の運航）の寄港全体で見る。今日の行だけで判断しない（例：今日 22:00 に出て翌日に次の港に着く便）
- **臨時便が始発港より後から出る・終点の手前で終わる**：その臨時便の最初の港より前、最後の港より後の港は抜港に数えない。最初と最後の港のあいだで寄らない港だけを抜港とする
- **同じ日・同じ方向に臨時便が2つ以上**：どれか1つでも抜港があれば「抜港あり」。時刻は今までどおりいちばん早い臨時便
- **便検索の行と臨時便がぶつかった港**（12 の「臨時便 HH:MM発あり」）：その港は定期便の行として残っている。抜港には数えない（寄港する）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: トップの会社カードで、今日その方向に「臨時便」の行が1つ以上あり、ふだんのバッジが「✓ 通常運航」または「○ 運航予定」になる航路は、バッジを「▲ スケジュール変更」にしなければならない。航路単位から決まる場合も、途中の港を出る便から決まる場合も同じ。臨時便が全部出港済みでも、その日は元のバッジに戻さない
- **FR-002**: FR-001 以外（欠航・運休・条件付・遅延・不明・情報なし・便なし・臨時便しか無い日の「◆ 臨時便」）のバッジと注意書きは、今までどおりでなければならない
- **FR-003**: 臨時便の1行（「◆ 臨時便 〇〇 HH:MM発」）は、バッジが変わっても今までどおり出さなければならない
- **FR-004**: 今日その方向の臨時便のうち1つでも、その臨時便の最初の港と最後の港のあいだにある定期便の寄港地に寄らないものがあれば、臨時便の1行の後ろに「・抜港あり」を出さなければならない。寄らないとは、その港に同じ船の行が無いか、あっても欠航・運休・抜港であること（同じ船の臨時便、または走る状態の定期便の行があれば寄港とする）
- **FR-005**: 「▲ スケジュール変更」のバッジは、今の「スケジュール変更」と同じ見た目・同じリンク先（会社詳細ページ）でなければならない
- **FR-006**: 通知メールで、航路×日付が通常運航で、通常以外の港の行に臨時便が1つでもあるとき、状況の頭を「スケジュール変更」にしなければならない（すべて臨時便なら「スケジュール変更（臨時便あり）」、ほかも混ざれば「スケジュール変更（途中の港に変更あり）」）。ほかの状況の文言は変えない
- **FR-007**: 臨時便が無い日の、会社カード・会社詳細・港別ページ・通知メールの表示は今と同じでなければならない
- **FR-008**: 会社を問わない（マルエーフェリー・マリックスラインのどちらにも効く）
- **FR-009**: 会社詳細ページ・港別ページの便の行、異常の要約、凡例は変えない
- **FR-010**: 12・13 の契約（`contracts/ui-status.md`・`contracts/notification-mail.md`）のうち、この機能で変える決まりは、この機能の契約で上書きしたことが分かるようにしなければならない

### Key Entities

- **臨時便の行**（既存）：港別の行のうち状態が「臨時便」のもの。船・方向・港・出港予定を持つ
- **定期便の寄港地**（既存）：航路ごとの港の並び。抜港かどうかの判断に使う

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 2026-10-27 のマルエー下りの形のデータで、会社カードのバッジが「通常運航」にならない（テストで再現）
- **SC-002**: 今日その方向に臨時便があり、航路単位が通常運航・運航予定になる航路のすべてで、緑の「通常運航」が出ない
- **SC-003**: 臨時便が無い日のトップ・会社詳細・港別・通知メールの表示が、変更前と1文字も変わらない（既存のテストがそのまま通る）
- **SC-004**: 2026-10-27 下り・2026-09-07 上りの形で「抜港あり」が出て、2026-09-27 上りの形で出ない

## Assumptions

- 「今日その方向に臨時便がある」の判断は、今の臨時便の1行と同じもの（今日その方向の「臨時便」の行。出港済みも含む）を使う。バッジと1行が食い違わないようにするため
- 抜港の判断は、同じ船の寄る行（臨時便、または走る状態の定期便）のあるなしで行う。マルエーフェリー（12 の FR-006）・マリックスライン（13 の FR-003）とも、臨時便が寄らない港には行を作らないので、会社を問わず同じ判断でよい
- 「抜港あり」は会社カードの1行だけに出す。どの港を抜くかは会社詳細ページで見てもらう（カードを長くしない）
- バッジを変えても、航路単位（データ）は変えない。スクレイパーは触らない。表示と通知メールの文言だけを変える
- 通知メールの件名・送る条件・港の行の並びは変えない

## Out of Scope

- 会社詳細ページ・港別ページに、日・方向ごとのまとめのバッジを足すこと
- 臨時便の1行に抜港の港名を並べること
- スクレイパーで、臨時便を航路単位に書くこと（13 の FR-008 のまま）
