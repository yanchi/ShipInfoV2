# Research: 臨時便がある日の会社カードのバッジ

## R1: バッジを「スケジュール変更」にする場所

**Decision**: `StatusController` で航路ごとのバッジ（今の `routesDepartingMidway()`）を組み立てた後に、臨時便がある航路を「changed」に変える処理を足す。配列とテンプレートの変数は `routeBadges` に名前を変える（航路単位が便なしでない航路も入るため）。

変える条件（FR-001）：今日その方向に `firstExtraDepartureOf()` が返す臨時便があり、ふだんのバッジが次のどちらか。

| ふだんのバッジの出どころ | 条件 |
|---|---|
| 航路単位（`routeBadges` に無い航路） | 航路単位の状態が `Operating` |
| `midwayDisplay()` の `badge` | `status` が `Operating`、または `state` が `Scheduled` |

`changed` のときテンプレートは今の「▲ スケジュール変更」のリンク（会社詳細ページへ）を出し、注意書きは出さない（今の `changed` と同じ。FR-005）。臨時便の1行はそのまま出る（FR-003）。

**Rationale**: 判定に使う材料（航路単位の状態・`midwayDisplay()` の結果・`firstExtraDepartureOf()`）は、今のコントローラーに全部そろっている。テンプレートの分岐（`changed` / `badge` / 航路単位）は変えずに済む。

**Alternatives considered**:
- Twig 側で `routesWithExtra` を見て分岐する：条件がテンプレートとコントローラーに分かれ、テストしにくい。却下
- `midwayDisplay()` の中で臨時便を数える：航路単位から決まる航路（今日の例はこちら）を拾えない。却下

## R2: 「臨時便がある」の判定

**Decision**: 今の臨時便の1行と同じ `PortBoardDay::firstExtraDepartureOf()`（今日・その方向・状態 `Extra`・出港時刻あり。出港済みも含む）を使う。

**Rationale**: バッジと1行が食い違わない（spec Assumptions）。出港後も戻さない（Clarifications）。抜粋で欠航などになった臨時便の行は状態が `Extra` でないので数えない（spec Edge Cases）。

## R3: 「抜港あり」の判定

> **16-extra-skip-flag で変更**：ボードの行から逆算するのをやめ、スクレイパーが臨時便の行に書く `skips_ports_after` を読むだけにした（[16 の research R1〜R5](../16-extra-skip-flag/research.md)）。下の `extraSkipsPortsOf()`・`isCalling()`・`noServiceShipNames` は消した。経緯として残す。

**Decision**: `PortBoard` に、その会社・その方向について「今日を出る臨時便のうち、抜港があるものがあるか」を返すメソッドを足す。

1. ボードの全日付から、その会社・その方向の状態 `Extra` のエントリーを集める（港の行の並び＝寄港順の位置と一緒に）
2. **船名と到着予定（`arrivalAt`）が同じもの**を1回の運航とする。臨時便の行の到着予定は、どの港の行も終点への到着（マルエー 12：便の終点の入港、マリックス 13 の FR-004：詳細ページの終点の入港）なので、同じ運航なら同じになる。10/27 の波之上は名瀬・本部とも 13:50着
3. 船名が空・null、または到着予定が null のエントリーはまとめない（1つで1回の運航。最初と最後が同じなので抜港は出ない。分からないときは「抜港あり」と言わない側に倒す）
4. 今日を出るエントリーを含む運航だけを見る
5. その運航の最初と最後の位置のあいだにある港のうち、運航の出港日の範囲で、同じ会社・同じ船のエントリーが「寄る」（`PortBoardEntry::isCalling()`）ものが無い港があれば「抜港あり」
   - 寄る：状態 `Extra`、または走る状態（運航予定・通常運航・条件付遅延・不明）。12 の「便検索の行とぶつかった港」は便検索（定期便）の行が残るので、寄港として数える
   - 寄らない：欠航・運休・抜港・行なし・便なし・情報なし
   - 状態の判定は `PortBoardEntry` のメソッドにする（`isDeparture()`・`isAlert()` と並べる）。`OperationStatusEnum` に状態が増えたとき、ほかの判定と一緒に見直せるように

`PortBoardExtraDeparture`（`final readonly class`）のコンストラクタに、昇格引数 `public bool $skipsPorts = false` を足す（readonly のプロパティ宣言には既定値を書けない）。`routesWithExtra()` で詰める。テンプレートは `{% if extra.skipsPorts %}・抜港あり{% endif %}`。

**Rationale**:
- 臨時便は寄らない港の行を作らない（マルエー 12 の FR-006、マリックス 13 の FR-003）。同じ船の寄る行が無いことで抜港と分かり、会社を問わない
- 運航を寄港順の位置だけで区切ると、同じ船・同じ方向で日が離れた臨時便（今日 名瀬だけ、2日後に本部だけ）が1つにつながり、あいだの港を抜港と取り違える（PR #94 レビュー）。到着予定でまとめれば、別の運航は到着予定が違うので混ざらない
- 寄港かどうかは、運航の出港日の範囲にある同じ船の行で見る（定期便の行は到着予定が臨時便と同じとは限らないので、到着予定では絞らない）。同じ日に同じ船が別の運航でその港に寄ると、それも寄港に数える（抜港を見落とす）。同じ船の臨時便が1日に2回出た例は無いので割り切る
- 日をまたぐ運航（今日 22:00 発・翌日に次の港）は、ボードの4日分から同じ船の続きを拾える。前日に始発港を出た運航（10/27 の名瀬 03:50）は、ボードに前日の行が無いので今日の最初の港からになる。それより前の港は数えない（spec Edge Cases）
- 寄港順の位置はボードの行の並び（`findBoardStops()`）。今の4航路は2社とも同じ港・同じ順なので、ボードの並びをそのまま使える
- マリックス 9/7 上り（那覇・名瀬が臨時便、本部〜亀徳は定期便の欠航の行）は、本部〜亀徳が欠航なので抜港。spec の US2-3 どおり

**Alternatives considered**:
- 寄港順の位置が前に進まなくなったところで切る：日が離れた別の臨時便がつながる（上）。日付が変わる・時刻が一定以上空くで切る案も、日をまたぐ運航（今日 22:00 名瀬 → 翌 06:00 亀徳）と見分ける閾値が要る。却下
- 行の詳細の「寄港いたしません」を読む：マルエーにしかない。マリックスは h2・h4 の文で、書き方が決まっていない。却下
- `route_stops` を会社ごとに読む：今は2社とも同じ港の並びなので不要。会社ごとに並びが変わる航路が来たら考える

**PR #95 レビューで足したこと**（判断できないときは「抜港あり」と言わない側に倒す）:
- 会社の航路に無い港は数えない：ボードの行は最初の航路の寄港順なので、`extraSkipsPortsOf()` に会社の航路の港 ID を渡し、そこに無い位置は飛ばす。航路に停泊地が無ければ言わない
- 便検索の no_service の行に隠れた寄港：マルエーは同じ船・港・日の便検索の行があると臨時便の行を作らず、その行が no_service だと `PortBoardBuilder` のルール2で落ちる（ほかの会社の便がある港のルール2・3でも同じ）。船名つきの no_service の行の船名を、その港の行の全エントリーに残し（`noServiceShipNames`。画面には出さない）、同じ船なら寄港に数える
- 船名か到着予定が無い臨時便は運航にまとめられないので見ない。見るのは今日と明日の行だけ
- 抜港かどうかをスクレイパーが臨時便の行にフラグで持つ案は別の変更（Issue）。入ったらここは読み取りだけになる

## R4: 通知メール

**Decision**: `IrregularService::statusText()` で、航路×日付が通常運航（`$operating`）で、港の行に Extra が1つでもあれば、状況の頭を「通常運航」から「スケジュール変更」にする（FR-006）。

| 港の行 | 状況 |
|---|---|
| 全部 Extra | スケジュール変更（臨時便あり） |
| Extra とそれ以外 | スケジュール変更（途中の港に変更あり） |
| Extra なし | 通常運航（途中の港に変更あり）（今のまま） |

航路×日付が便なし・行なしのとき（「臨時便あり」「情報なし（途中の港に変更あり）」）と、欠航などのときは変えない。

**Rationale**: 航路×日付が通常運航の日について、サイト（R1）と同じく「通常運航」と書かない。「スケジュール変更」はトップのバッジの文言と同じ。件名・送る条件・港の並びは変えない。

サイトと条件をそろえないところ：航路×日付が便なし・行なしで、途中の港の定期便が通常運航・運航予定、臨時便もある日。サイトは「▲ スケジュール変更」、メールは「臨時便あり」（または「情報なし（途中の港に変更あり）」）。

- メールに載るのは通常以外の港の行だけ（`findIrregularBetween()`）。途中の港の定期便が通常運航かは、メールの組み立てでは分からない。そろえるには通常運航の行も読む必要があり、この機能に見合わない
- どちらの文言も「通常運航」とは書かず、港の行に「臨時便」が並ぶので、読み違いは起きない

**Alternatives considered**: 全部 Extra のときだけ変える：臨時便と欠航が混ざる日に「通常運航」と書いてしまい、サイトと食い違う。却下

## R5: 今あるテストへの影響

FR-001 で振る舞いが変わるので、次のテストの期待を書き換える（決まりを変えたことはテストの名前・説明にも書く）。

| テスト | 今の期待 | 変更後 |
|---|---|---|
| `StatusControllerTest::testIndexCardOriginExtraWithMidwayRegularKeepsRegularBadge` | ✓ 通常運航 | ▲ スケジュール変更 |
| `StatusControllerTest::testIndexCardMidwayRegularPlusExtraKeepsRegularBadge` | ✓ 通常運航・スケジュール変更なし | ▲ スケジュール変更 |
| `IrregularServiceCollectorTest` の「通常運航・全部 Extra」 | 通常運航（臨時便あり） | スケジュール変更（臨時便あり） |
| `IrregularServiceCollectorTest::testStatusTextForExtraPorts` の「Extra と条件付が混ざる」（通常運航＋Extra＋Delayed） | 通常運航（途中の港に変更あり） | スケジュール変更（途中の港に変更あり） |

`testIndexCardShowsExtraDepartureUnderRouteBadge`（航路単位が欠航）・`testIndexCardOriginExtraKeepsCancelledBadge`・`testIndexCardMidwayCancelledPlusExtraShowsCancelled` は欠航のままなので変わらない（FR-002）。

臨時便の行が1港だけのテストは、運航の最初と最後が同じなので「抜港あり」は付かない。今の `◆ 臨時便 名瀬 13:00発` などの完全一致はそのまま通る。
