# Feature Specification: 出発港別の運航情報表示

**Feature Branch**: `4-departure-port-status`
**Created**: 2026-10-01
**Status**: Ready for Planning
**Input**: User description: "運航情報を出発港ごとに表示したい。到着港は固定：上り＝鹿児島着、下り＝那覇着。（例：下りなら「鹿児島発→那覇」「名瀬発→那覇」「与論発→那覇」…）"

## 概要

現状の運航情報は会社ごとに「鹿児島〜那覇（下り）」「那覇〜鹿児島（上り）」の2行しか表示されず、途中港（名瀬・亀徳・和泊・与論・本部）から乗る利用者は自分の港から船が出るのかを判断できない。
本機能では、到着港を方向ごとに固定（下り＝那覇着、上り＝鹿児島着）したうえで、**出発港ごとの行**として運航状況を表示する。

```
下り（那覇行き）            上り（鹿児島行き）
  鹿児島発 → 那覇              那覇発 → 鹿児島
  名瀬発   → 那覇              本部発 → 鹿児島
  亀徳発   → 那覇              与論発 → 鹿児島
  和泊発   → 那覇              和泊発 → 鹿児島
  与論発   → 那覇              亀徳発 → 鹿児島
  本部発   → 那覇              名瀬発 → 鹿児島
```

### 取得元データの制約（前提）

| 会社 | 取れる情報 | 方向 | 寄港地情報 |
|------|-----------|------|-----------|
| マルエーフェリー | 方向・日付別の便検索結果（船名）＋船単位のステータス（鹿児島航路ページ）＋船別詳細ページの運航状況テキスト | 「方向（出発港・到着港・日付で便検索）→ 船名 → 船ステータス」の順で取得するため、船ごとに方向と始発日を特定可能 | 運航状況テキストに港別の情報（条件付寄港・抜港・港変更など）が含まれることがある |
| マリックスライン | 便単位のステータス（運航状況一覧）＋便別詳細ページの港別ステータス・港別入出港日時 | 便ごとに取得可（鹿児島発 / 那覇発） | 便別詳細ページに港ごとのステータス（通常運航／条件付運航など）と入出港日時が構造化されて掲載される |

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自分の乗る港から船が出るか確認できる (Priority: P1)

奄美・沖縄の途中港（例：名瀬）から那覇へ向かう利用者として、「名瀬発→那覇」の行を見るだけで、今日その港から乗れるかどうか（通常運航・条件付・欠航・便なし）を知りたい。

**Why this priority**: 本機能の存在理由。途中港の利用者は現状、航路全体のステータスから自分の港への影響を推測するしかない。

**Independent Test**: マリックスラインの下り便が全港通常運航のデータを用意し、会社詳細ページに下り6行（鹿児島・名瀬・亀徳・和泊・与論・本部 → 那覇）がすべて「通常運航」で表示されることで単独確認できる。

**Acceptance Scenarios**:

1. **Given** マリックスラインの下り便（鹿児島発）が全港通常運航, **When** 利用者が運航情報を開く, **Then** 下りセクションに「鹿児島発→那覇」〜「本部発→那覇」の6行が港の運航順に並び、すべて「通常運航」と表示される
2. **Given** マリックスラインの上り便（那覇発）が欠航, **When** 利用者が運航情報を開く, **Then** 上りセクションの「那覇発→鹿児島」〜「名瀬発→鹿児島」の6行がすべて「欠航」と表示される
3. **Given** マリックスラインの上り便が当日存在しない, **When** 利用者が運航情報を開く, **Then** 上りセクションの全行が「便なし」と表示される
4. **Given** 9月30日に鹿児島を出た下り便が欠航、10月1日に鹿児島を出る下り便が通常運航（名瀬以降は始発翌日に出港）, **When** 利用者が10月1日に会社詳細ページを開く, **Then** 「鹿児島発→那覇（10/1）」は通常運航、「名瀬発→那覇（10/1）」〜「本部発→那覇（10/1）」は欠航と表示される（10/1 にその港を実際に出る便＝9/30 鹿児島発の便のステータス）
5. **Given** 出発港別表示の実装後, **When** 利用者がトップページを開く, **Then** 会社カードは従来どおり上り・下り2行で表示される

### User Story 2 - 条件付寄港地が港ごとに区別される (Priority: P1)

与論港から乗る利用者として、船全体は運航していても「与論港は条件付寄港」の場合は、与論発の行だけが条件付として目立つように表示されてほしい。

**Why this priority**: 出発港別表示の価値が最も出るケース。全港を一律「条件付」にすると、実際には影響のない港の利用者に誤った不安を与える。

**Independent Test**: マルエーフェリーの詳細テキストに「条件付寄港地: 和泊港、与論港」を含むデータを用意し、和泊発・与論発の行のみ「条件付」、他の港は「通常運航」になることで単独確認できる。

**Acceptance Scenarios**:

1. **Given** マルエーフェリーの下り便の船が条件付運航で、詳細に「条件付寄港地: 和泊港、与論港」と記載, **When** 利用者が運航情報を開く, **Then** 下りの和泊発・与論発の行が「条件付」、下りのそれ以外の港の行は「通常運航」と表示される
2. **Given** マルエーフェリーの下り便の船が条件付運航で、詳細に寄港地の記載がない, **When** 利用者が運航情報を開く, **Then** 下りの全港の行が「条件付」と表示される
3. **Given** 条件付寄港地として表示されている行, **When** 利用者がその行を見る, **Then** 公式サイトの詳細テキストが併せて表示される
4. **Given** マリックスラインの上り便が便全体「条件付運航」で、便別詳細ページでは与論港・和泊港が「条件付運航」、他の港が「通常運航」, **When** 利用者が運航情報を開く, **Then** 上りの与論発・和泊発の行のみ「条件付」、他の港の行は「通常運航」と表示される

### User Story 3 - マルエーフェリーは船ごとの方向と運航状況テキストの港別情報で判定される (Priority: P1)

マルエーフェリーの利用者として、各船がどちらの方向の便かを踏まえたうえで、運航状況テキストに書かれた港別の情報（条件付寄港・抜港・港変更など）が自分の港の行に反映されてほしい。

**Why this priority**: マルエーフェリーは船単位のステータスで提供される。船の方向と港別テキストを組み合わせないと、別方向の船の情報が混ざり港別表示の意味がなくなる。

**Independent Test**: 方向別の便検索結果（下り：フェリーあけぼの、上り：フェリー波之上）と、船ステータス（あけぼの：欠航、波之上：通常運航）のデータを用意し、各方向の行がその方向の船のステータス・港別情報だけで判定されることで単独確認できる。

**Acceptance Scenarios**:

1. **Given** 下り便の船が欠航、上り便の船が通常運航, **When** 利用者が運航情報を開く, **Then** 下りの全出発港行が「欠航」、上りの全出発港行が「通常運航」と表示される（他方向の船のステータスは混ざらない）
2. **Given** 当日便が存在しない, **When** 利用者が運航情報を開く, **Then** その方向の全出発港行が「便なし」と表示される
3. **Given** 下り便の船のテキストに「与論港は抜港」と記載, **When** 利用者が運航情報を開く, **Then** 下りの与論発の行は「欠航」、下りの他の港の行は船ステータスで表示され、与論発の行にはテキストが併記される
4. **Given** 下り便の船のテキストに「亀徳港から平土野港へ港変更」と記載, **When** 利用者が運航情報を開く, **Then** 下りの亀徳発の行は「条件付」と表示され、港変更の内容がテキストで併記される
5. **Given** 下り便の船のテキストに「与論港は抜港」と記載、上り便の船は通常運航, **When** 利用者が運航情報を開く, **Then** 下りの与論発の行のみ「欠航」、上りの与論発の行は「通常運航」と表示される
6. **Given** 便検索結果の船名が船ステータスの一覧と対応付けられない, **When** 利用者が運航情報を開く, **Then** その船の情報は上り・下り両方の該当行に反映され、warning ログが残る（フォールバック）
7. **Given** 下りの便検索結果が「※下記参照（マリックスライン）」のみ, **When** 利用者が運航情報を開く, **Then** マルエーフェリーの下りの全出発港行が「便なし」と表示される

### User Story 4 - 途中港の実際の出発日で見られる (Priority: P1)

名瀬から那覇へ向かう利用者として、「今日名瀬を出る便」が前日に鹿児島を出た便であっても、今日の日付で正しいステータスを見たい。

**Why this priority**: 日またぎを無視すると、途中港の利用者に別の便（翌日着く便）のステータスを見せてしまい、乗れる・乗れないの判断を誤らせる。

**Independent Test**: 始発日の異なる2便（前日発・当日発）のデータを用意し、途中港の行が前日発の便、始発港の行が当日発の便のステータスになることで単独確認できる。

**Acceptance Scenarios**:

1. **Given** 下りで名瀬の出港が始発の翌日と定義されている, **When** 利用者が10月1日の運航情報を見る, **Then** 「名瀬発→那覇」の行は9月30日鹿児島発の便のステータスを表示し、行に出発日「10/1」が明記される
2. **Given** 上りで全途中港の出港が始発当日と定義されている, **When** 利用者が10月1日の運航情報を見る, **Then** 上りの全行は10月1日那覇発の便のステータスを表示する
3. **Given** その港を当日出る便（前日始発の便）のデータが一度も取得できていない, **When** 利用者が運航情報を見る, **Then** その行は「情報なし」と表示され、別の日の便のステータスで代用しない
4. **Given** 会社詳細ページの複数日表示, **When** 利用者が日付ごとの表示を見る, **Then** 各日付の各行は、その日にその港を実際に出る便のステータスになっている
5. **Given** 前日始発の便が9/30 20:00 の取得を最後に公式ページから消えた, **When** 利用者が10/1 に運航情報を見る, **Then** 名瀬発以降の行はその便の最後のステータスを「9/30 20:00時点」と併記して表示する

---

### Edge Cases

- 詳細テキストの寄港地名が「和泊港」「和泊」など表記揺れしている場合でも、同じ港として認識される
- 詳細テキストに航路に存在しない港名（例：誤記）が含まれる場合、その港名は無視し、該当港の無い分は全体ステータスで表示する（warning ログを残す）
- 条件付寄港地の記載があるが、船全体のステータスが欠航の場合は、全港「欠航」を優先する
- 船全体のステータスが不明（unknown）・データ未取得の場合、全港「情報なし／不明」と表示する
- マルエーフェリーで同じ方向に複数の船の情報がある場合（通常は1方向1隻の想定）は、港ごとに最も深刻なものを採用する
- 出港済みの便が公式ページから消えた後に航海中の変更（途中での抜港など）があっても取得できない。この場合も最終取得時刻の表示によって、利用者が情報の鮮度を判断できるようにする
- マリックスラインの便別詳細ページの取得・解析に失敗した場合は、便全体のステータスと日数オフセットで表示し、warning ログを残す
- マリックスラインの便別詳細ページに航路マスタにない港が掲載された場合（港変更先など）は、その港の行は増やさず、warning ログを残す
- 前日始発の便が月末・年末をまたぐ場合も、日付計算が正しく行われる
- マルエーフェリーの運航状況テキストに日付の記載がない場合は、便検索の日付（始発日）の便の情報として扱い、日数オフセットで各港の出港日を求める
- 同じ港に複数の港別情報（例：条件付寄港と港変更）が記載された場合は、より深刻なもの（欠航 > 条件付）を採用する
- 港別情報の文言が既知のパターンに一致しない場合は船ステータスで表示し、抽出失敗として warning ログを残す（誤判定より取りこぼしを選ぶ）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは各方向について、到着港を固定（下り＝那覇、上り＝鹿児島）した出発港別の行を表示しなければならない
- **FR-002**: 出発港は航路の運航順に並べなければならない（下り：鹿児島→名瀬→亀徳→和泊→与論→本部、上り：那覇→本部→与論→和泊→亀徳→名瀬）
- **FR-003**: 出発港の一覧・順序は、コード変更なしで管理者が追加・変更できるマスタデータとして保持しなければならない
- **FR-004**: マリックスラインは、便別詳細ページに掲載された港ごとのステータスと出港日時を各出発港行に用いなければならない。便別詳細ページが取得できない場合は、便全体のステータスをその方向の全出発港に適用し、出港日は日数オフセットで求める（フォールバック）
- **FR-005**: マルエーフェリーは、方向（出発港・到着港）と日付を指定した便検索の結果から各方向の船名を特定し、その船のステータスをその方向の全出発港の既定値とし、運航状況テキストに含まれる港別情報で港ごとに上書きしなければならない。検索結果の船名が船ステータスの一覧と対応付けられない場合は、その船の情報を上り・下り両方に適用し、warning ログを残す（フォールバック）
- **FR-006**: 運航状況テキストから港別情報を抽出し、言及された港の行を次のとおり判定しなければならない：条件付寄港 →「条件付」、抜港 →「欠航」、港変更 →「条件付」（変更先の港名をテキスト併記）。言及のない港は船（便）全体のステータスとする（ただし船全体が「条件付」で港別情報が存在する場合、条件付の理由はその港にあるとみなし、言及のない港は「通常運航」とする）。また船全体が欠航・運休・便なしの場合は全港そちらを優先する
- **FR-007**: 港別情報はその船の方向の行にのみ反映しなければならない。出港日は便検索の日付（始発日）に日数オフセットを加えて求め、テキストに日付の記載がある場合はその記載を優先する
- **FR-008**: 港の行に公式サイトの詳細テキストがある場合は併せて表示しなければならない
- **FR-009**: 各行は「その日にその港を実際に出港する便」のステータスを表示し、各行に出港日を明記しなければならない。出港日は、公式に港別の出港日時が取得できる場合（マリックスラインの便別詳細ページ）はその値を用い、取得できない場合は便の始発日（下り＝鹿児島発日、上り＝那覇発日）に港ごとの日数オフセットを加えて求める
- **FR-010**: 出発港別表示は会社詳細ページにのみ適用しなければならない。会社詳細ページは現行の構成（直近3日分の日付セクション）を維持し、各日付セクション内を「下り／上り → 出発港行（運航順）」とする。日付セクションの日付は各港の出港日とする。トップページの会社カードは現状の上り・下り2行表示のまま変更しない
- **FR-011**: 既存の運航ステータス種別（通常運航・条件付・欠航・運休・便なし・不明）とその表示ラベル・色は変更してはならない
- **FR-012**: スクレイパーが収集する元データ（会社・便単位のステータスと詳細テキスト）は従来どおり記録し、港別の解釈が誤っていた場合でも元データから再解釈できなければならない
- **FR-013**: その港を当日出る便のステータスが一度も取得できていない場合は「情報なし」と表示し、別日の便のステータスで代用してはならない。一度でも取得できていれば、公式ページから掲載が消えた後も最後に取得したステータスを表示する
- **FR-014**: 各出発港行には、表示しているステータスの最終取得時刻（例：「10/1 6:00時点」）を表示しなければならない
- **FR-015**: マルエーフェリーの便検索で、その方向・日付の便が他社（マリックスライン）運航分しか無い場合（船名欄が「※下記参照」・会社名がマリックスライン）は、マルエーフェリーのその方向の行を「便なし」としなければならない

### Key Entities

- **港（Port）**: 航路上の寄港地。名称と表記揺れ（「和泊港」「和泊」）を吸収するための別名を持つ
- **航路の寄港順（Route Stop）**: 方向ごとの港の運航順と、始発港からの出港日数オフセット（例：下りの名瀬＝+1日。公式の港別出港日時が取れない場合に使う）。到着港（那覇 / 鹿児島）を終点とする
- **港別運航情報（Port Call）**: マリックスラインの便別詳細ページから取得した、便 × 港ごとのステータス・入港日時・出港日時・説明文
- **港別情報（Port Notice）**: マルエーフェリーの運航状況テキストから抽出した、港単位の情報（対象港・種別〔条件付寄港／抜港／港変更〕・変更先港・方向・日付〔記載があれば〕・元テキスト）
- **出発港別ステータス（Departure Status）**: 会社 × 方向 × 出発港 × 出港日ごとの表示用ステータス。港別運航情報（マリックスライン）または便（船）全体のステータス＋港別情報（マルエーフェリー）から導出される。出港日は港別出港日時、無ければ始発日＋オフセットで求める
- **船（Ship）**: マルエーフェリーの運航船（フェリーあけぼの・フェリー波之上）。便検索結果により日付ごとの方向（始発港・到着港）と対応付けられ、ステータス・運航状況テキストを持つ
- **Route（既存）**: 会社ごとの上り・下り2レコード。便（船）全体のステータスの記録先として引き続き使う

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は途中港（名瀬・亀徳・和泊・与論・本部）からの運航可否を、1画面・追加操作なしで確認できる
- **SC-002**: 条件付寄港地が記載された日、記載された港の行のみが「条件付」となり、記載外の港の行が誤って「条件付」と表示される件数が0件である
- **SC-003**: 会社詳細ページで、両社とも上り・下り各6行、計12行の出発港別ステータスが表示され、行の欠落が0件である
- **SC-004**: 本機能追加後も、既存のスクレイピング成功率・既存ステータス判定のテストが全件パスする
- **SC-005**: 新しい寄港地が増えた場合、マスタデータの追加のみで表示行が増える（コード修正0件）
- **SC-006**: 日またぎのある港（例：下りの名瀬以降）で、当日その港を実際に出る便とは別の便のステータスが表示される件数が0件である（両社）
- **SC-007**: 全ての出発港行で、表示中ステータスの取得時刻が画面上で確認できる
- **SC-008**: マリックスラインの各出発港行のステータスが、便別詳細ページに掲載された当該港のステータスと100%一致する

## Clarifications

### Session 2026-10-01

- Q: 途中港の日付基準（例：「今日の名瀬発」はどの便か） → A: その日にその港を実際に出る便のステータスを表示する（始発日＋港ごとの日数オフセットで換算）。※当初「換算しない」で合意したが、同日中に変更
- Q: 出発港別表示を行う画面 → A: 会社詳細ページのみ。トップページは現状の2行表示のまま
- Q: マルエーフェリーの港別表示はどう判定するか → A: 運航状況テキストに含まれる港別情報（条件付寄港・抜港・港変更、記載があれば方向・日付）を参照して港ごとに判定し、言及のない港は船ステータスとする
- Q: 前日始発の便が公式ページから消えた後の扱い → A: 最後に取得したステータスを表示し、各行に最終取得時刻を併記する（時間経過で「情報なし」には切り替えない）
- Q: 会社詳細ページの構成 → A: 暫定で現行構成を維持（直近3日分の日付セクション → 下り／上り → 出発港6行）。見せ方の改善は別要件で検討する
- Q: マリックスラインの港別ステータスと出港日の取得元 → A: 便別詳細ページの港別ステータス・出港日時を使う。日数オフセットはマルエーフェリーとマリックスラインのフォールバック用
- Q: マルエーフェリーの複数船の情報の扱い → A: スクレイピングの処理順（方向・日付指定の便検索 → 船名 → 船ステータス）で船ごとの方向と始発日を特定し、各船の情報はその方向の行にのみ反映する。対応付けできない場合のみ両方向に適用（フォールバック）

## Assumptions

- 両社とも鹿児島〜那覇航路の寄港地は共通で、鹿児島・名瀬・亀徳・和泊・与論・本部・那覇の7港とする（plan 段階で公式時刻表と照合）
- マリックスラインの便別詳細ページは運航状況一覧の各便からリンクされており、1回の取得あたりのリクエスト増は便数分（通常2〜4件）にとどまる
- マリックスラインの便別詳細ページの港名表記（「鹿児島新港」「名瀬港」など）は港マスタの別名で吸収する
- マルエーフェリーの方向は、既存スクレイパーの処理順（便検索〔方向・日付指定〕→ 鹿児島航路ページの船ブロック）に沿って、便検索結果の船名から特定する。上り方向は出発港・到着港を入れ替えた便検索で取得する
- マルエーフェリーの船ステータスは「船の現在の状況」であり、便検索の日付（始発日）の便に対応するものとみなす。前日始発の便の途中港分は、前日に取得した船ステータスを使う
- 港別情報の参照元は、鹿児島航路ページの抜粋テキストと船別詳細ページの運航状況テキスト。抜粋で切れる場合があるため詳細ページ側を正とする。具体的な文言パターン（条件付寄港・抜港・港変更・方向/日付の書き方）は plan 段階で実データ・過去事例を調査して確定する
- 港変更の変更先（平土野・伊延・茶花など）は表示用の補足情報として扱い、独立した出発港行は増やさない
- 到着港（那覇 / 鹿児島）発の行は存在しない（終点のため）
- 港ごとの日数オフセットは両社共通の時刻表に基づき、マスタデータで管理する。主な用途はマルエーフェリーとマリックスラインのフォールバック。値は plan 段階で公式時刻表から確定する（現時点の想定：下りは名瀬以降が始発翌日、上りは全港が始発当日）
- 途中港の当日分を表示するには前日始発の便のステータスが必要。2026-10-01 時点の確認では、マリックスラインの運航状況一覧に前日（9/30）発の便が翌日も掲載されていた。掲載が消えた後は最後に取得したステータスを使う（掲載期間は plan 段階で調査）
- 既存スクレイパーは共同運航（他社運航）の検索結果行も「便あり」と判定しているが、方向別判定では他社運航分を除外する（FR-015）

## Out of Scope

- 那覇→名瀬、名瀬→与論など、到着港が固定の2港以外になる区間別表示
- 港ごとの発着時刻の表示
- 会社詳細ページの見せ方の改善（行数削減・レイアウト変更など。暫定構成からの見直しは別要件）
- トップページの出発港別表示、会社をまたいだ港別統合ページ（反応を見て別 spec で検討）
- 過去データの港別再計算・遡及表示
- 鹿児島〜那覇航路以外の航路
