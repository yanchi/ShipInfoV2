# Feature Specification: 出発港別の運航情報表示

**Feature Branch**: `4-departure-port-status`
**Created**: 2026-10-01
**Status**: Ready for Planning
**Input**: User description: "運航情報を出発港ごとに表示したい。到着港は固定：上り＝鹿児島着、下り＝那覇着。（例：下りなら「鹿児島発→那覇」「名瀬発→那覇」「与論発→那覇」…）"

## 概要

現状の運航情報は会社ごとに「鹿児島〜那覇（下り）」「那覇〜鹿児島（上り）」の2行しか表示されず、途中港（名瀬・亀徳・和泊・与論・本部）から乗る利用者は自分の港から船が出るのかを判断できない。
本機能では、到着港を方向ごとに固定（下り＝那覇着、上り＝鹿児島着）したうえで、**出発港ごとの行**として運航状況を表示する。

```
下り（那覇行き）            上り（鹿児島行き）
  鹿児島発 → 那覇              那覇発 → 鹿児島
  名瀬発   → 那覇              本部発 → 鹿児島
  亀徳発   → 那覇              与論発 → 鹿児島
  和泊発   → 那覇              和泊発 → 鹿児島
  与論発   → 那覇              亀徳発 → 鹿児島
  本部発   → 那覇              名瀬発 → 鹿児島
```

### 取得元データの制約（前提）

| 会社 | 取れる情報 | 方向 | 寄港地情報 |
|------|-----------|------|-----------|
| マルエーフェリー | 船単位のステータス（鹿児島航路ページ） | 区別なし | 詳細テキストに「条件付寄港地: 和泊港、与論港」等が含まれることがある |
| マリックスライン | 便単位のステータス | 便ごとに取得可（鹿児島発 / 那覇発） | なし（便全体のステータスのみ） |

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自分の乗る港から船が出るか確認できる (Priority: P1)

奄美・沖縄の途中港（例：名瀬）から那覇へ向かう利用者として、「名瀬発→那覇」の行を見るだけで、今日その港から乗れるかどうか（通常運航・条件付・欠航・便なし）を知りたい。

**Why this priority**: 本機能の存在理由。途中港の利用者は現状、航路全体のステータスから自分の港への影響を推測するしかない。

**Independent Test**: マリックスラインの下り便が通常運航のデータを用意し、会社詳細ページに下り6行（鹿児島・名瀬・亀徳・和泊・与論・本部 → 那覇）がすべて「通常運航」で表示されることで単独確認できる。

**Acceptance Scenarios**:

1. **Given** マリックスラインの下り便（鹿児島発）が通常運航, **When** 利用者が運航情報を開く, **Then** 下りセクションに「鹿児島発→那覇」〜「本部発→那覇」の6行が港の運航順に並び、すべて「通常運航」と表示される
2. **Given** マリックスラインの上り便（那覇発）が欠航, **When** 利用者が運航情報を開く, **Then** 上りセクションの「那覇発→鹿児島」〜「名瀬発→鹿児島」の6行がすべて「欠航」と表示される
3. **Given** マリックスラインの上り便が当日存在しない, **When** 利用者が運航情報を開く, **Then** 上りセクションの全行が「便なし」と表示される
4. **Given** 10月1日に鹿児島を出る下り便のデータ, **When** 利用者が会社詳細ページを開く, **Then** 下りセクションに「10月1日 鹿児島発の便」と対象便の日付が明記され、名瀬発以降の行も同じ便のステータスとして読み取れる
5. **Given** 出発港別表示の実装後, **When** 利用者がトップページを開く, **Then** 会社カードは従来どおり上り・下り2行で表示される

---

### User Story 2 - 条件付寄港地が港ごとに区別される (Priority: P1)

与論港から乗る利用者として、船全体は運航していても「与論港は条件付寄港」の場合は、与論発の行だけが条件付として目立つように表示されてほしい。

**Why this priority**: 出発港別表示の価値が最も出るケース。全港を一律「条件付」にすると、実際には影響のない港の利用者に誤った不安を与える。

**Independent Test**: マルエーフェリーの詳細テキストに「条件付寄港地: 和泊港、与論港」を含むデータを用意し、和泊発・与論発の行のみ「条件付」、他の港は「通常運航」になることで単独確認できる。

**Acceptance Scenarios**:

1. **Given** マルエーフェリーのステータスが条件付運航で、詳細に「条件付寄港地: 和泊港、与論港」と記載, **When** 利用者が運航情報を開く, **Then** 上り・下り両方の和泊発・与論発の行が「条件付」、それ以外の港の行は「通常運航」と表示される
2. **Given** マルエーフェリーのステータスが条件付運航で、詳細に寄港地の記載がない, **When** 利用者が運航情報を開く, **Then** 全港の行が「条件付」と表示される
3. **Given** 条件付寄港地として表示されている行, **When** 利用者がその行を見る, **Then** 公式サイトの詳細テキストが併せて表示される

---

### User Story 3 - 方向が取れない会社でも港別に見られる (Priority: P2)

マルエーフェリーの利用者として、公式サイトが上り・下りを区別していなくても、他社と同じ「出発港別」の形式で状況を確認したい。

**Why this priority**: 両社で表示形式を揃えないと利用者が混乱する。ただし方向情報が無い分、精度は US1 より低い前提で許容する。

**Independent Test**: マルエーフェリーの船ステータスが欠航のデータを用意し、上り・下り両セクションの全行が「欠航」と表示されることで確認できる。

**Acceptance Scenarios**:

1. **Given** マルエーフェリーの船ステータスが欠航, **When** 利用者が運航情報を開く, **Then** 上り・下り両方の全出発港行が「欠航」と表示される
2. **Given** マルエーフェリーの当日便が存在しない, **When** 利用者が運航情報を開く, **Then** 上り・下り両方の全出発港行が「便なし」と表示される

---

### Edge Cases

- 詳細テキストの寄港地名が「和泊港」「和泊」など表記揺れしている場合でも、同じ港として認識される
- 詳細テキストに航路に存在しない港名（例：誤記）が含まれる場合、その港名は無視し、該当港の無い分は全体ステータスで表示する（warning ログを残す）
- 条件付寄港地の記載があるが、船全体のステータスが欠航の場合は、全港「欠航」を優先する
- 船全体のステータスが不明（unknown）・データ未取得の場合、全港「情報なし／不明」と表示する
- マルエーフェリーで複数船のステータスが異なる場合は、既存の方針どおり最も深刻なものを採用する
- 寄港地情報が「抜港（寄港しない）」形式で記載された場合の扱いは plan 段階で公式サイトの実例を調査して決める（本 spec では「条件付寄港地」形式のみ必須）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは各方向について、到着港を固定（下り＝那覇、上り＝鹿児島）した出発港別の行を表示しなければならない
- **FR-002**: 出発港は航路の運航順に並べなければならない（下り：鹿児島→名瀬→亀徳→和泊→与論→本部、上り：那覇→本部→与論→和泊→亀徳→名瀬）
- **FR-003**: 出発港の一覧・順序は、コード変更なしで管理者が追加・変更できるマスタデータとして保持しなければならない
- **FR-004**: 方向が取得できる会社（マリックスライン）は、各便のステータスをその方向の全出発港に適用しなければならない
- **FR-005**: 方向が取得できない会社（マルエーフェリー）は、船ステータスを上り・下り両方の全出発港に適用しなければならない
- **FR-006**: 詳細テキストに条件付寄港地が列挙されている場合、列挙された港の行を「条件付」、列挙されていない港の行を「通常運航」として表示しなければならない（船全体が欠航・運休・便なしの場合は全港そちらを優先）
- **FR-007**: 条件付寄港地の列挙がない場合は、船（便）全体のステータスを全港にそのまま適用しなければならない
- **FR-008**: 港の行に公式サイトの詳細テキストがある場合は併せて表示しなければならない
- **FR-009**: 各行のステータスは「その日に始発港（下り＝鹿児島、上り＝那覇）を出る便」のものを全出発港に適用し、行（またはセクション）に対象便の日付を「○月○日 鹿児島発の便」のように明記しなければならない（途中港の実際の出発日への換算は行わない）
- **FR-010**: 出発港別表示は会社詳細ページにのみ適用しなければならない。トップページの会社カードは現状の上り・下り2行表示のまま変更しない
- **FR-011**: 既存の運航ステータス種別（通常運航・条件付・欠航・運休・便なし・不明）とその表示ラベル・色は変更してはならない
- **FR-012**: スクレイパーが収集する元データ（会社・便単位のステータスと詳細テキスト）は従来どおり記録し、港別の解釈が誤っていた場合でも元データから再解釈できなければならない

### Key Entities

- **港（Port）**: 航路上の寄港地。名称と表記揺れ（「和泊港」「和泊」）を吸収するための別名を持つ
- **航路の寄港順（Route Stop）**: 方向ごとの港の運航順。到着港（那覇 / 鹿児島）を終点とする
- **出発港別ステータス（Departure Status）**: 会社 × 方向 × 出発港 × 日付ごとの表示用ステータス。便（船）全体のステータスと条件付寄港地情報から導出される
- **Route（既存）**: 会社ごとの上り・下り2レコード。便（船）全体のステータスの記録先として引き続き使う

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者は途中港（名瀬・亀徳・和泊・与論・本部）からの運航可否を、1画面・追加操作なしで確認できる
- **SC-002**: 条件付寄港地が記載された日、記載された港の行のみが「条件付」となり、記載外の港の行が誤って「条件付」と表示される件数が0件である
- **SC-003**: 会社詳細ページで、両社とも上り・下り各6行、計12行の出発港別ステータスが表示され、行の欠落が0件である
- **SC-006**: 利用者が各行のステータスがどの日に始発港を出た便のものかを、画面上の表記だけで判別できる
- **SC-004**: 本機能追加後も、既存のスクレイピング成功率・既存ステータス判定のテストが全件パスする
- **SC-005**: 新しい寄港地が増えた場合、マスタデータの追加のみで表示行が増える（コード修正0件）

## Clarifications

### Session 2026-10-01

- Q: 途中港の日付基準（例：「今日の名瀬発」はどの便か） → A: その日に始発港を出る便のステータスを全港に適用し、「○月○日 鹿児島発の便」のように対象便の日付を明記する（途中港の実出発日への換算はしない）
- Q: 出発港別表示を行う画面 → A: 会社詳細ページのみ。トップページは現状の2行表示のまま

## Assumptions

- 両社とも鹿児島〜那覇航路の寄港地は共通で、鹿児島・名瀬・亀徳・和泊・与論・本部・那覇の7港とする（plan 段階で公式時刻表と照合）
- マリックスラインの便は鹿児島発・那覇発ともに全寄港地を経由する前提とし、便ステータスを全港に適用する（港別の抜港情報は取得できない）
- マルエーフェリーは方向が判別できないため、同じステータスを上り・下り両方に適用する（現行方針の踏襲）。精度上の限界として許容する
- 条件付寄港地の抽出対象は「条件付寄港地: ○○港、△△港」形式のテキスト。具体的な抽出パターンは plan 段階で実データを調査して確定する
- 条件付寄港地の対象方向は特定できないため、上り・下り両方の該当港に適用する
- 到着港（那覇 / 鹿児島）発の行は存在しない（終点のため）

---

## Out of Scope

- 那覇→名瀬、名瀬→与論など、到着港が固定の2港以外になる区間別表示
- 港ごとの発着時刻の表示、および途中港の実際の出発日（日またぎ）への換算
- トップページの出発港別表示、会社をまたいだ港別統合ページ（反応を見て別 spec で検討）
- マルエーフェリーの方向判別（公式サイトが提供していないため）
- 過去データの港別再計算・遡及表示
- 鹿児島〜那覇航路以外の航路
