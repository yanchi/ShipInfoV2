# Feature Specification: 運航情報画面の見やすさ改善

**Feature Branch**: `5-ui-readability`
**Created**: 2026-10-01
**Status**: Draft
**Input**: User description: "画面分析してもっと見やすい画面にできないか検討して"

## 概要

現状の3画面（トップ・会社別・港別）を分析し、利用者が「今日（または近日）自分の港から船が出るか」を最短で判断できる画面に改善する。
データの収集方法・保持内容は変えず、**表示の構成と見せ方だけ**を変える。

### 現状分析（2026-10-01 時点の実画面）

| 画面 | 問題 | 利用者への影響 |
|------|------|---------------|
| 共通 | ヘッダー・ナビゲーションが無く、画面間の移動は「← トップへ戻る」「港別に見る →」の小さなリンクだけ | 港別ページの存在に気付きにくい。港別→会社別への移動手段が無い |
| 共通 | 情報が「いつ時点」のものかがトップ・会社別に出ていない | 古い情報を見ているのか判断できない |
| 共通 | 「○ 運航予定」「— 便なし」「情報なし」が似た淡い見た目で、色だけで区別している部分がある | 状態の違いが一目で分からない。色覚多様性への配慮が弱い |
| トップ | 会社ごと × 航路（上り/下り）2行だけ。出発港も出港時刻も分からない | 途中港の利用者は自分の港の状況がトップで分からず、本命の港別ページへのリンクも目立たない |
| トップ | その日運航しない会社（例：マリックスライン 10/1）も「便なし」2行を大きなカードで表示 | 意味の薄い情報が画面を占める |
| 会社別 | 表示する日付が「今日・昨日・一昨日」と過去向きで、過去日はほぼ「情報なし」 | 利用者が知りたい「明日以降」が見られない。無意味な「情報なし」が並ぶ |
| 港別 | 4日 × 2方向 × 6港 = 最大48行を縦に全部並べる | スマートフォンでは非常に長いスクロールになり、自分の港・日付を探すのが大変 |
| 港別 | 「10/1 21:18時点」がすべての行に繰り返し出る。同じ船が各港に寄るため船名・会社名も行ごとに繰り返される | 視線のノイズが多く、ステータスと時刻が埋もれる |
| 港別 | 欠航・条件付などの異常が、48行の中に通常運航と同じ並びで混ざる | 異常があっても見落としやすい |
| 港別 | 1行の中で「ステータス・船名／会社・出港時刻・（着時刻）・確認時刻」が横に流れ、スマートフォンでは折り返して読みにくい | 一番知りたい「何時発・運航するか」が読み取りにくい |

### 改善の方針

1. **自分の港を起点にする**：港と方向を選ぶと、その港の便だけが日付順に並ぶ
2. **異常を先に見せる**：欠航・条件付・情報なしなどは画面上部に要約して出す
3. **繰り返しを減らす**：確認時刻は日付ごと（またはページ上部）にまとめる
4. **未来を見せる**：会社別ページは今日以降を表示する
5. **迷わないナビゲーション**：全ページ共通のヘッダーで画面を行き来できる

## Clarifications

### Session 2026-10-01

- Q: 港別ページで日付をどう見せるか（移動 / タブ切り替え / 折りたたみ） → A: 全日付を縦に並べたまま、上部に固定の日付ボタンを置き押すとその日付へ移動する（A案）。実装後の実画面を確認して、タブ切り替え（1日分だけ表示）に変える可能性あり
- Q: 会社別ページで何を並べるか（便の行のみ / 航路要約＋便の行 / 航路単位のまま） → A: 日付ごとに、上に航路単位のステータスと詳細文を1行の要約で出し、その下に出発港ごとの便の行を並べる（B案）
- Q: 「情報が古い」をどう判定するか（全体2時間 / 全体6時間 / 行ごと） → A: サイト全体で最も新しい確認時刻で判定し、2時間以上前なら全ページ上部に警告を出す。行ごとには判定しない（A案）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自分の港の便だけを見る (Priority: P1)

途中港（例：和泊）から乗る利用者として、港別ページで自分の港と方向を選び、その港から出る便だけを日付順に見たい。次に開いたときも同じ港が選ばれていてほしい。

**Why this priority**: 港別ページの最大の問題（48行の長いスクロール）を直接解消する。利用者の主目的「自分の港から船が出るか」に一番効く。

**Independent Test**: 港別ページで「和泊発・下り（那覇行き）」を選ぶと、今日〜3日先の和泊発→那覇の行だけが表示されることで単独確認できる。

**Acceptance Scenarios**:

1. **Given** 港別ページを初めて開いた, **When** 何も選ばない, **Then** これまで通り全港・両方向が表示される（選択していない人の見え方は情報量を減らさない）
2. **Given** 港別ページ, **When** 出発港「和泊」・方向「下り（那覇行き）」を選ぶ, **Then** 今日〜3日先の「和泊発→那覇」の行だけが日付順に表示される
3. **Given** 出発港「和泊」だけを選び方向は「両方向」, **When** 表示する, **Then** 各日付で「和泊発→那覇」「和泊発→鹿児島」の2行が表示される
4. **Given** 前回「和泊・下り」を選んでページを閉じた, **When** 同じ端末で港別ページを開き直す, **Then** 「和泊・下り」が選ばれた状態で表示され、「全港に戻す」操作で解除できる
5. **Given** 「和泊・下り」を選んだ状態のURL, **When** そのURLを他の人に送って開いてもらう, **Then** 相手の画面でも「和泊・下り」が選ばれた状態で表示される
6. **Given** 港を選んでいる, **When** 画面を見る, **Then** 「和泊発のみ表示中」のように絞り込み中であることが分かる

---

### User Story 2 - 欠航・条件付などの異常を最初に知る (Priority: P1)

利用者として、ページを開いた瞬間に「今日〜数日先に欠航や条件付運航があるか」を知りたい。異常が無ければ「すべて通常運航（予定）」と分かれば十分。

**Why this priority**: 運航情報サイトで一番重要なのは異常の通知。現状は異常が通常運航の行に埋もれている。

**Independent Test**: 10/2 名瀬発→那覇を「条件付・遅延」にしたデータで港別ページとトップを開き、画面上部の要約に「10/2 名瀬発→那覇 条件付・遅延」が出ることで単独確認できる。

**Acceptance Scenarios**:

1. **Given** 表示期間内に「欠航」「条件付・遅延」「運休」の便がある, **When** 港別ページまたはトップを開く, **Then** 画面上部（スクロールせずに見える位置）に、該当する日付・出発港・方向・ステータスの一覧が要約として表示される
2. **Given** 要約の項目, **When** 項目を選ぶ, **Then** その日付・港の行の位置へ移動する
3. **Given** 表示期間内の便がすべて「通常運航」または「運航予定」, **When** ページを開く, **Then** 要約には「表示期間内に欠航・条件付の便はありません」と表示される
4. **Given** 港を絞り込んでいる（US1）, **When** 要約を見る, **Then** 要約も絞り込んだ港・方向の分だけになる
5. **Given** 欠航・条件付の行, **When** 一覧の中で見る, **Then** 行全体が通常運航の行と明確に違う見た目（背景や枠など、色以外の手がかりも含む）で表示される

---

### User Story 3 - 港別の行を一目で読める (Priority: P1)

利用者として、港別ページの各行で「何時発か」「運航するか」をまず読み取り、船名・会社・着時刻は補足として見たい。

**Why this priority**: 港を絞り込んでも、行自体が読みにくければ価値が落ちる。US1・US2 と合わせて港別ページの体験が完成する。

**Independent Test**: 港別ページをスマートフォン幅（幅 375px 相当）で表示し、各行で出港時刻とステータスが1行目に並び、船名・会社・着時刻が2行目以降に小さく出ること、確認時刻が行ごとに繰り返されないことで単独確認できる。

**Acceptance Scenarios**:

1. **Given** 便がある行, **When** スマートフォン幅で表示, **Then** 1行目に「出発港 → 到着港」「出港時刻」「ステータス」が並び、船名／会社・着時刻は補足として下に表示される
2. **Given** 同じ日・同じ方向の複数行が同じ時刻に確認された, **When** 表示, **Then** 確認時刻は日付（または方向）の見出し付近に1回だけ表示され、行ごとには繰り返されない
3. **Given** 一部の行だけ確認時刻が他と異なる, **When** 表示, **Then** その行にだけ確認時刻が表示される
4. **Given** 着時刻が出港日の翌日, **When** 表示, **Then** 「翌08:30着」のように日付をまたぐことが分かる表記になる（現状の表記を維持）
5. **Given** 4日分のデータ, **When** 港別ページを開く, **Then** 全日付が縦に並んで表示され、ページ上部の日付ボタンを押すとその日付の位置へ移動する
6. **Given** ページを下までスクロールした, **When** 画面上部を見る, **Then** 日付ボタンは画面上部に残ったまま表示されている

---

### User Story 4 - トップで今日の状況をつかむ (Priority: P2)

利用者として、トップページを開いたら、今日の運航状況（どの港から何時に出るか）と異常の有無がすぐ分かり、詳しい港別ページへ迷わず進みたい。

**Why this priority**: トップは最初に開く画面だが、現状は会社×方向の2行しか無く途中港の利用者の役に立たない。ただし港別ページ（US1〜3）が改善されていれば最低限の目的は果たせるため P2。

**Independent Test**: トップを開き、異常の要約（US2）、今日の方向ごとの便の概要、港別ページへの目立つ導線が表示されることで単独確認できる。

**Acceptance Scenarios**:

1. **Given** トップを開く, **When** 画面を見る, **Then** 異常の要約（US2）が最上部に表示される
2. **Given** 今日、下り・上りそれぞれに便がある, **When** トップを見る, **Then** 方向ごとに「船名／会社・始発港の出港時刻・ステータス」が表示され、港別ページへのはっきりした導線（ボタン相当の大きさ）がある
3. **Given** 前回港別ページで「和泊・下り」を選んでいた（US1）, **When** トップを開く, **Then** 「和泊発→那覇」の今日の便が目立つ位置に表示される
4. **Given** その日運航が無い会社がある, **When** トップを見る, **Then** その会社は「本日運航なし」の1行程度に縮めて表示され、運航する会社より目立たない
5. **Given** トップ, **When** 画面を見る, **Then** 情報の最終確認時刻が表示される

---

### User Story 5 - 会社別ページで今日以降を見る (Priority: P2)

利用者として、会社別ページでその会社の今日以降の運航予定を見たい。過去の「情報なし」は不要。

**Why this priority**: 現状の会社別ページは過去日中心でほぼ役に立たない。ただし利用頻度はトップ・港別より低いため P2。

**Independent Test**: 会社別ページを開き、今日以降の日付だけが今日から順に表示され、昨日以前が表示されないことで単独確認できる。

**Acceptance Scenarios**:

1. **Given** 10/1 に会社別ページを開く, **When** 画面を見る, **Then** 10/1 から未来方向に日付が並び、9/30 以前は表示されない
2. **Given** 会社別ページ, **When** ある日付を見る, **Then** 日付の見出しの下に、まず航路ごと（下り・上り）のステータスと詳細文が1行の要約で表示され、その下にその会社の便が港別ページと同じ行の構成（出発港・出港時刻・ステータスが主、船名・着時刻が補足）で出発港ごとに並ぶ
3. **Given** ある日その会社の便が無い, **When** 画面を見る, **Then** その日は「便なし」の1行で表示され、航路ごとの「情報なし」を並べない
4. **Given** ある日の航路単位の情報が無いが便単位の情報はある, **When** 画面を見る, **Then** 航路の要約行は表示せず、便の行だけを表示する（「情報なし」の要約行を出さない）

---

### User Story 6 - 全ページ共通のナビゲーションと状態表示 (Priority: P3)

利用者として、どのページからでもトップ・港別・各社ページへ移動でき、ステータスの表示が全ページで同じ見た目・同じ意味であってほしい。

**Why this priority**: 体験の一貫性を上げるが、単独での価値は US1〜5 より小さい。

**Independent Test**: 3画面すべてに同じヘッダー（サイト名・トップ・港別・各社へのリンク）があり、ステータス表示の凡例と見た目が全画面で一致することで単独確認できる。

**Acceptance Scenarios**:

1. **Given** どのページ, **When** 画面上部を見る, **Then** サイト名と「トップ」「港別」「各社」へのリンクを含む共通ヘッダーが表示され、今いるページが分かる
2. **Given** すべてのステータス（通常運航・運航予定・条件付・遅延・欠航・運休・便なし・情報なし・不明）, **When** 表示, **Then** それぞれがアイコン（記号）・文言・色の組み合わせで区別でき、色が無くても文言と記号だけで判別できる
3. **Given** 「運航予定」「便なし」「情報なし」, **When** 並べて表示, **Then** 3つが一目で別物と分かる見た目になる
4. **Given** 港別ページ, **When** ステータスの意味が分からない, **Then** 凡例（各ステータスの意味の短い説明）を参照できる

---

### Edge Cases

- **すべてのデータが無い**（スクレイパー停止直後など）：各画面は現状通り「現在情報がありません」を表示し、異常の要約は表示しない（「異常なし」と誤解させない）
- **情報が古い**：サイト全体で最も新しい確認時刻が現在から2時間以上前の場合、全ページ上部に「情報が古い可能性があります」の警告を出す。先の日付の便は確認の間隔が長い（最大6時間程度）ため、行ごとの確認時刻では古さを判定しない
- **保存されている港が存在しなくなった**：前回選んだ港が表示対象から外れた場合は選択を解除し全港表示に戻す
- **URL の港指定が不正**：存在しない港・方向が指定された場合は全港表示にする（エラー画面にしない）
- **同じ日・同じ港に2社の便がある**（臨時便など）：両方の便を出港時刻順に並べ、異常の要約にもそれぞれ出す
- **出発済みの便**：今日の便で出港時刻が過ぎたものは表示を控えめにする（消さない）
- **「情報なし」の扱い**：「情報なし」は異常の要約に含めるが、欠航・条件付とは別の区分（「確認できていない便」）として出す
- **端末に選択を保存できない**（プライベートブラウズ等）：保存できなくても絞り込み自体は動作し、URL で状態を保持できる
- **非常に長い詳細テキスト**：運航状況の詳細文（└ の行）が長い場合は数行で省略し、全文を展開して読める

## Requirements *(mandatory)*

### Functional Requirements

**港別ページ**

- **FR-001**: 港別ページは出発港（全港 / 各港）と方向（両方向 / 下り / 上り）で表示する行を絞り込めなければならない
- **FR-002**: 絞り込みの状態はURLに反映され、そのURLを開くと同じ絞り込み状態で表示されなければならない
- **FR-003**: 最後に選んだ絞り込みは同じ端末に保存され、次回絞り込み指定なしでページを開いたときに適用されなければならない。利用者はいつでも全港表示に戻せなければならない
- **FR-004**: 絞り込み中であることと、絞り込みの内容が画面上で分からなければならない
- **FR-005**: 各行は「出発港 → 到着港」「出港時刻」「ステータス」を主情報とし、船名／会社・着時刻・詳細文を補足情報として、主情報より控えめに表示しなければならない
- **FR-006**: 確認時刻は、同じ見出し（日付・方向）配下の行で共通ならば見出し付近に1回だけ表示し、異なる行にのみ行ごとに表示しなければならない
- **FR-007**: 港別ページは表示期間（今日〜3日先）の全日付を縦に並べて表示し、上部に日付ボタンを置かなければならない。日付ボタンはスクロールしても画面上部に残り、押すとその日付の位置へ1操作で移動できなければならない（実画面の確認後、1日分だけを表示するタブ切り替えに変更する可能性がある）
- **FR-008**: 今日の便で出港時刻を過ぎたものは、まだ出港していない便より控えめに表示しなければならない（非表示にはしない）

**異常の要約**

- **FR-009**: トップと港別ページの上部に、表示期間内の「欠航」「条件付・遅延」「運休」の便を一覧で要約しなければならない。各項目は日付・出発港・方向・ステータスを含む
- **FR-010**: 「情報なし」の便は、FR-009 とは別の区分（確認できていない便）として要約に含めなければならない
- **FR-011**: 該当する便が無い場合は「表示期間内に欠航・条件付の便はありません」と表示しなければならない。ただしデータ自体が無い場合はこの文言を出してはならない
- **FR-012**: 要約の各項目から該当する行の位置へ移動できなければならない
- **FR-013**: 港別ページで絞り込み中は、要約も絞り込み条件に従わなければならない
- **FR-014**: 一覧中の欠航・条件付・運休の行は、色以外の手がかり（記号・枠・太字など）も用いて通常の行と区別できなければならない

**トップページ**

- **FR-015**: トップは上から順に「異常の要約」「（保存された港がある場合）その港の今日の便」「方向ごとの今日の便の概要」「会社一覧」の構成としなければならない
- **FR-016**: 方向ごとの今日の便の概要は、船名／会社・始発港の出港時刻・ステータスを含まなければならない
- **FR-017**: 港別ページへの導線は、本文中の小さなテキストリンクではなく、ボタン相当の大きさで目立つ位置に置かなければならない
- **FR-018**: その日運航の無い会社は、運航する会社より小さく（1行程度に）まとめて表示しなければならない

**会社別ページ**

- **FR-019**: 会社別ページは今日から未来方向（今日〜3日先）の日付を表示し、昨日以前の日付は表示してはならない
- **FR-020**: 会社別ページは日付ごとに、(1) 航路ごと（下り・上り）のステータスと詳細文の1行要約、(2) その会社の出発港ごとの便の行、の順で表示しなければならない。(2) の行は港別ページの行と同じ主情報・補足情報の構成とする。航路単位の情報が無い日は (1) を表示しない
- **FR-021**: 便の無い日は「便なし」の1行で表示しなければならない

**共通**

- **FR-022**: 全ページに共通ヘッダー（サイト名、トップ・港別・各社へのリンク、現在ページの表示）を置かなければならない
- **FR-023**: 全ページにサイト全体の最終確認時刻（全データのうち最も新しい確認時刻）を表示しなければならない。最終確認時刻が現在から2時間以上前の場合は、全ページ上部に注意の見た目で「情報が古い可能性があります」の警告を出さなければならない。行ごとの確認時刻では古さを判定してはならない
- **FR-024**: ステータス表示は全ページで同じ見た目・同じ文言とし、各ステータスは記号・文言・色の組み合わせで、色なしでも判別できなければならない
- **FR-025**: 「運航予定」「便なし」「情報なし」は互いに一目で区別できる見た目でなければならない
- **FR-026**: ステータスの凡例（各ステータスの意味の短い説明）を参照できなければならない
- **FR-027**: すべての画面はスマートフォン幅（幅 375px 相当）で横スクロールなしに表示できなければならない
- **FR-028**: 長い詳細文は既定で数行に省略し、利用者の操作で全文を表示できなければならない
- **FR-029**: 「最新情報は各社公式サイトをご確認ください」の注意書きと各社公式サイトへのリンクは維持しなければならない

### Key Entities

既存データをそのまま使い、新しいデータは追加しない。

- **便の表示行**: 日付・方向・出発港・到着港・出港時刻・着時刻・船名・会社・ステータス・詳細文・確認時刻（港別ページで既に使っている情報）
- **異常の要約項目**: 便の表示行のうち、ステータスが欠航・条件付・遅延・運休・情報なしのものを、日付・出発港・方向・ステータスで要約したもの
- **絞り込み条件**: 出発港（全港 or 1港）と方向（両方向 / 下り / 上り）。URLと利用者の端末に保持され、サーバーには保存しない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めての利用者が、スマートフォンで港別ページを開いてから「明日の和泊発那覇行きが運航するか」を答えるまでの操作が3操作以内・15秒以内で完了する
- **SC-002**: 港を1つ・方向を1つに絞り込んだとき、港別ページの縦の長さが絞り込み前の 1/5 以下になる
- **SC-003**: 2回目以降の訪問では、操作なしで自分の港の便が最初の画面（スクロールなし）に表示される
- **SC-004**: 表示期間内に欠航・条件付の便が1件でもあれば、トップ・港別ページともにスクロールせずに見える範囲でその事実が分かる
- **SC-005**: 港別ページの1日あたりの「〜時点」表記の出現回数が、行数ではなく見出しの数以下（全行同時刻の場合）になる
- **SC-006**: 会社別ページに昨日以前の日付が表示されない
- **SC-007**: 全ステータスを白黒（グレースケール）表示にしても、文言と記号だけで全種類を判別できる
- **SC-008**: 3画面すべてが幅 375px で横スクロールなしに表示される
- **SC-009**: 既存のテスト済みの表示内容（ステータス判定・便の振り分け・着時刻表記）が改善後も同じ結果を返す（表示の改善によって情報の正しさが変わらない）

## Assumptions

- 主な利用者は奄美・沖縄航路の乗船予定者で、スマートフォンからの閲覧が中心と想定する（モバイルファーストで設計する）
- 表示期間（今日〜3日先）、対象港・方向、ステータスの種類と判定ロジックは現状のまま変えない
- データの収集・保持方法（スクレイパー・DB）は変更しない。表示に必要な情報は既存データから得られる
- 絞り込み条件の保存はログイン不要で、利用者の端末内にのみ保存する（サーバーには個人の情報を保存しない）
- 「情報が古い」の閾値は 2 時間とする（情報の確認は通常30分ごとに行われるため、4回続けて確認できなければ気付ける長さ）
- 自動更新（ページを開いたまま最新化する機能）、通知（メール・プッシュ）、ダークモード、多言語対応は本機能の範囲外
- 会社別ページの便の行は、港別ページで使っている便単位の情報から得る。航路の要約行は既存の航路単位の情報から得る
- 見た目の改善は既存の画面部品の範囲で行い、外部のデザインシステム導入はしない
