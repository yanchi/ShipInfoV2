# Feature Specification: V1 の見た目・ファビコン・OG を引き継ぐ

**Feature Branch**: `7-v1-branding`
**Created**: 2026-10-05
**Status**: Draft
**Input**: User description: "V1と差し替えるためにファビコン・OGをV1に合わせてページのテイストをV1に合わせて"

## 概要

V2 を、いま公開している V1（`https://ship.isl-mentor.com/`、リポジトリ `../ShipInfo`）と差し替える。
差し替えても、V1 の利用者が「同じサイトが新しくなった」と感じられるように、**ファビコン・OG（SNS でシェアしたときの表示）・ページのテイスト**を V1 にそろえる。
V2 で作った画面の構成・機能（トップ・港別・会社別、共通ヘッダー、異常の要約、最終確認時刻など）は変えず、**見た目とサイトの名乗り方だけ**を変える。

### 現状の差分（2026-10-05 時点）

| 項目 | V1 | V2 |
|------|----|----|
| ファビコン | 青地にフェリーと波の絵（オリジナル SVG） | 黒丸に「sf」の仮アイコン |
| サイト名 | 鹿児島〜沖縄・奄美大島 フェリー運航情報 | ShipInfo |
| ページタイトル | `<ページ名> \| 鹿児島〜沖縄フェリー運航状況` | `ShipInfo - フェリー運航情報`（全ページ同じ） |
| 説明文（description） | ページごとにあり | なし |
| OG / Twitter カード | og:title・og:description・og:url・og:type・og:site_name、twitter:card=summary | なし |
| canonical | あり | なし |
| ヘッダー | 青（#0073e6）の帯に白抜きのサイト名を中央寄せ、その下に白いナビ | 白地に下線、左寄せの「ShipInfo」と小さなリンク |
| 背景・カード | 薄いグレー（#f4f4f9）の背景に、白い角丸＋影のカード | 白地、標準的なカード |
| 見出し | 青い下線つきの h2 | 下線なし |
| ステータス表示 | 角丸のバッジ。通常=緑、遅延・条件付=黄、欠航=赤、運休=グレー、寄港地変更=青、スケジュール変更=紫 | 似た色分けだが、色味・形が V1 と異なる |
| フッター | 濃いグレーの帯に「© 2025 鹿児島〜沖縄・奄美大島 フェリー運航情報サービス」 | なし |
| 文字 | ヒラギノ角ゴ・游ゴシック | 端末の標準 |

## Clarifications

### Session 2026-10-05

- Q: サイト名をどうするか（V1 の名前に完全にそろえる / 併記 / ShipInfo を主にする） → A: V1 の名前に完全にそろえ、「ShipInfo」はどこにも出さない
- Q: ヘッダーの並べ方（V1 と同じ配置でナビ1行 / V1 と完全に同じでスマホは縦積み / 1行に左右配置） → A: V1 と同じ配置（サイト名を中央、その下にナビを中央寄せ）。スマートフォン幅でもナビは縦に積まず1行のまま
- Q: V1 の `/details/today` で来た人をどこに案内するか → A: 港別ページへ恒久的に転送する
- Q: アクセス解析（Google Analytics）をどうするか → A: V1 と同じ。本番で解析 ID が設定されているときだけ計測タグを出し、V1 と同じ ID を引き継ぐ

## User Scenarios & Testing *(mandatory)*

### User Story 1 - V1 と同じサイトだと分かる（Priority: P1）

V1 をブックマークやホーム画面に入れている利用者が、差し替え後に開いたとき、ブラウザのタブ・ブックマーク・ホーム画面のアイコンも、ページの見た目（青いヘッダー・薄いグレーの背景・白いカード・フッター）も V1 と同じで、「いつものサイトだ」と迷わず使える。

**Why this priority**: 差し替えの目的そのもの。見た目が別物になると「別サイト・偽サイトに飛んだ」と思われ、利用者が離れる。

**Independent Test**: V1 と V2 のトップ・港別・会社別を同じ幅（375px と 1280px）で並べ、ファビコン・ヘッダー・背景・カード・見出し・ステータスの色・フッターが V1 と同じテイストに見えることを目で確認する。

**Acceptance Scenarios**:

1. **Given** V2 のどのページを開いても、**When** ブラウザのタブを見ると、**Then** V1 と同じフェリーの絵のファビコンが出る
2. **Given** V2 のどのページを開いても、**When** 画面上部を見ると、**Then** V1 と同じ青い帯に白い文字でサイト名「鹿児島〜沖縄・奄美大島 フェリー運航情報」が中央に出て、その下に V2 のナビ（トップ・港別・各社）が白い文字で中央寄せに1行で並ぶ（375px 幅でも1行）
3. **Given** V2 のどのページを開いても、**When** 画面下部まで見ると、**Then** V1 と同じ濃いグレーのフッターに V1 と同じ著作権表示が出る
4. **Given** 欠航・条件付・遅延・運休・通常運航の便があるとき、**When** その便を見ると、**Then** ステータスは V1 と同じ配色の角丸バッジで出る（色だけでなく文字・記号でも区別できる、という V2 の決まりは保つ。寄港地変更・スケジュール変更は FR-013 のとおり条件付・遅延か欠航として出る）
5. **Given** スマートフォン幅（375px）で開いたとき、**When** 画面全体を見ると、**Then** 横スクロールが出ず、ヘッダー・ナビ・フッターが崩れない

---

### User Story 2 - SNS・チャットでシェアすると V1 と同じように表示される（Priority: P1）

利用者が LINE・X などにページの URL を貼ったとき、V1 と同じサイト名・ページタイトル・説明文のカードが出る。検索結果にも V1 と同じ形式のタイトルと説明文が出る。

**Why this priority**: 運航情報は家族・同行者にシェアされやすい。差し替えで説明文の無い素の URL になると、クリックされにくく、検索での見え方も悪くなる。

**Independent Test**: 各ページの HTML の `<head>` を確認し、タイトル・説明文・OG・Twitter カード・canonical がそろっていることを確かめる。SNS のカード確認ツール（または OG を読み取るツール）に URL を入れ、V1 と同じ形式で表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** トップページ、**When** `<head>` を見ると、**Then** タイトルは「鹿児島〜沖縄・奄美大島フェリー運航情報」（V1 のトップと同じ）、説明文は扱っている会社名と区間・更新頻度を含む文になっている
2. **Given** トップ以外のページ（港別・会社別）、**When** `<head>` を見ると、**Then** タイトルは「<ページ名> | 鹿児島〜沖縄フェリー運航状況」の形式で、ページの内容に合った説明文がある（会社別は会社名を含む）
3. **Given** どのページでも、**When** `<head>` を見ると、**Then** og:title・og:description・og:url・og:type・og:site_name（「鹿児島〜沖縄フェリー運航情報サービス」）・twitter:card（summary）・canonical が出ている
4. **Given** og:url と canonical、**When** 値を見ると、**Then** そのページ自身の URL（クエリ文字列を除く）になっている

---

### User Story 3 - V1 の URL で来た人・検索エンジンが迷わない（Priority: P2）

V1 のブックマークや検索結果（`/`、`/details/today`）から来た利用者が、エラーページではなく V2 の対応するページにたどり着く。検索エンジン向けの robots.txt・sitemap.xml も V2 のページ構成に合わせて出る。

**Why this priority**: 差し替えると V1 だけにあった URL が無くなる。放っておくと「ページが見つかりません」になり、検索順位も落ちる。ただし見た目（P1）が先。

**Independent Test**: `/details/today` を開き、V2 の対応するページへ恒久的に転送されることを確かめる。`/robots.txt` と `/sitemap.xml` を開き、V2 のページが載っていることを確かめる。

**Acceptance Scenarios**:

1. **Given** V1 の URL `/details/today`、**When** 開くと、**Then** V2 の港別ページへ恒久的な転送（移転済みを示す転送）で移る
2. **Given** `/robots.txt`、**When** 開くと、**Then** すべてのページのクロールを許可し、sitemap.xml の場所が書いてある
3. **Given** `/sitemap.xml`、**When** 開くと、**Then** トップ・港別・有効な各社ページの URL が載っている

### Edge Cases

- ナビの「各社」ドロップダウンは、青い帯の中でも開いたメニューが読める配色になること（白地のメニューに濃い文字など）
- 古い情報の警告（最終確認から一定時間たったとき）は、V1 のテイストの中でも目立つこと（警告の黄色を青ヘッダーに埋もれさせない）
- 会社が1社も無いとき・運航情報が無いときの「情報なし」表示も、V1 と同じテイスト（薄い背景・斜体の灰色の文字など）で出ること
- 港別ページの上に固定される日付ボタンは、背景がグレーになっても後ろの内容が透けないこと
- 会社別ページで存在しない会社 ID を開いたときのエラーページも、ヘッダー・フッターつきの同じテイストで出ること（少なくともファビコンとサイト名は同じ）
- ダークモードの端末でも、V1 と同じ明るい配色で表示すること（V1 はダークモードに対応していない）

## Requirements *(mandatory)*

### Functional Requirements

**ファビコン**

- **FR-001**: すべてのページで、V1 と同じファビコン（V1 の `favicon.svg` と同じ絵）を出すこと
- **FR-002**: V1 と同じ URL（`/favicon.svg`）でもファビコンを取得できること（V1 のブックマークに残っているアイコンの参照先を保つ）

**サイト名・タイトル・説明文**

- **FR-003**: サイト名を V1 と同じ「鹿児島〜沖縄・奄美大島 フェリー運航情報」にし、ヘッダーに出すこと。ヘッダーのサイト名はトップページへのリンクにすること。「ShipInfo」という名前は画面・タイトル・説明文・OG のどこにも出さないこと
- **FR-004**: トップページのタイトルは「鹿児島〜沖縄・奄美大島フェリー運航情報」、それ以外のページは「<ページ名> | 鹿児島〜沖縄フェリー運航状況」とすること
- **FR-005**: すべてのページに、そのページの内容を表す説明文（description）を出すこと。会社別ページは会社名を含めること

**OG・検索向けの情報**

- **FR-006**: すべてのページに og:title・og:description・og:url・og:type（website）・og:site_name（「鹿児島〜沖縄フェリー運航情報サービス」）・twitter:card（summary）を出すこと。og:title はページタイトル、og:description は説明文と同じにすること
- **FR-007**: すべてのページに canonical を出し、og:url と同じ、そのページ自身の URL（スキーム・ホストを含み、クエリ文字列を除く）にすること
- **FR-008**: OG 画像は V1 に無いため、今回は出さないこと（V1 と同じ表示にそろえる）
  - 10-og-image で置き換えた（全ページ共通の OG 画像を出し、twitter:card を summary_large_image にする）

**ページのテイスト**

- **FR-009**: ヘッダーは V1 と同じ青（#0073e6）の帯に、白い文字のサイト名を中央寄せで出し、その下にナビ（トップ・港別・各社）を白い文字で中央寄せに出すこと。ナビは 375px 幅でも縦に積まず1行に収めること（V1 はスマートフォン幅で縦に積むが、V2 では採らない）。いまいるページはナビ上で分かること（V2 の決まりを保つ）
- **FR-010**: ページの背景を V1 と同じ薄いグレー（#f4f4f9）、本文の文字色を V1 と同じ濃いグレー（#333）、文字の書体を V1 と同じ（ヒラギノ角ゴ・游ゴシック系）にすること
- **FR-011**: 会社・日付・港などのまとまりは、V1 と同じ白い角丸＋薄い影のカードで出すこと
- **FR-012**: 大見出しは V1 と同じ、青い下線つきの見出しにすること
- **FR-013**: ステータスのバッジは、V1 と同じ配色・角丸の形にすること（通常=緑、遅延・条件付=黄、欠航=赤、運休・情報なし=グレー）。V2 で決めた「色だけに頼らず文字・記号でも区別する」「異常の行を強調する」は保つこと。V1 の「寄港地変更（青）」「スケジュール変更（紫）」は、V2 に対応するステータスが無いので作らない（V2 では航行経路変更は条件付・遅延、抜港は欠航として出す。#54）。区別して出すのは、V2 のステータスに足すときに別の機能として行う
- **FR-014**: すべてのページの下に、V1 と同じ濃いグレー（#333）の帯のフッターを出し、V1 と同じ著作権表示を出すこと
- **FR-015**: 375px から 1280px 以上の幅まで、横スクロールが出ずに表示できること（V1 と同じく、狭い幅ではヘッダー・ナビの文字を小さくする）
- **FR-016**: V1 の注意書き「出港時間・寄港地が変更になってる可能性があるので公式サイトをご確認ください」を、欠航・条件付・遅延の便に V1 と同じ赤い小さな文字で出すこと。V1 は遅延の便には出さないが、V2 は条件付と遅延が1つのステータス（条件付・遅延）なので、遅延だけの便にも出す。V1 の寄港地変更・スケジュール変更は、V2 では欠航か条件付・遅延に含まれるので、この2つで V1 と同じ範囲になる

**V1 の URL・検索エンジン向けファイル**

- **FR-017**: V1 の `/details/today` を開いたら、V2 の港別ページへ恒久的に転送すること（V1 の「航路詳細」に当たるのは、出港時刻とステータスが分かる港別ページとする）
- **FR-018**: `/robots.txt` で、すべてのページのクロールを許可し、`/sitemap.xml` の場所を示すこと
- **FR-019**: `/sitemap.xml` に、トップ・港別・有効な各社ページの URL を載せること。URL のスキーム・ホストはリクエストのものにすること（本番では `https://ship.isl-mentor.com` になる。ローカルや v2 のホストで開いたときに本番を指さないように）。robots.txt の sitemap の場所も同じ

**変えないもの**

- **FR-020**: 画面の構成（どのページに何を出すか）、ナビの項目、異常の要約、最終確認時刻・古い情報の警告、日付ボタン、絞り込みは、V2 の現状から変えないこと（見た目だけを V1 にそろえる）
**アクセス解析**

- **FR-021**: 本番で解析 ID が設定されているときだけ、すべてのページに V1 と同じアクセス解析（Google Analytics）の計測タグを出すこと。ID は V1 と同じものを引き継ぎ、差し替えの前後で計測が途切れないようにすること
- **FR-022**: 本番以外（ローカル・CI）や、解析 ID が設定されていないときは、計測タグを出さず、外部の解析サービスへ何も送らないこと

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: V2 の全ページ（トップ・港別・会社別・エラーページ）で、ファビコンが V1 と同じ絵になっている（3ページ＋エラーページで 100%）
- **SC-002**: V2 の全ページで、タイトル・説明文・og:title・og:description・og:url・og:type・og:site_name・twitter:card・canonical の 9 項目がすべて出ている
- **SC-003**: V1 と V2 のトップを並べて見せたとき、確認した人が「同じサイト」と答える（開発者＋第三者 1 名以上で確認）
- **SC-004**: 375px 幅のスマートフォン表示で、全ページに横スクロールが出ない
- **SC-005**: V1 の URL（`/`、`/details/today`）がどちらもエラーにならず、V2 のページが表示される
- **SC-006**: 画面の構成・機能に関する既存のテストが、変更後もすべて通る（見た目の変更で機能が壊れていない）

## Assumptions

- 「V1」は、いま `https://ship.isl-mentor.com/` で公開しているサイト（リポジトリ `../ShipInfo`）を指す。V1 のファビコン・配色・文言はそのリポジトリの現状を正とする
- 差し替え後も同じドメイン（`ship.isl-mentor.com`）で公開する前提。sitemap・robots の URL はこのドメインにする
- 扱う会社はV1・V2とも同じ（Aライン〈マルエーフェリー〉・マリックスライン）。説明文の会社名もこの2社を前提にする
- V1 の「お問い合わせ」はナビで非表示になっているため、引き継がない
- フッターの著作権表示の年は V1 と同じ「2025」とする（サービス開始年として扱う）
- V2 のページ名（「港別」「各社」など）はそのまま使い、V1 の文言（「航路詳細」など）には変えない

## Out of Scope

- 画面の構成・機能の変更（V2 の 5-ui-readability で決めた内容は変えない）
- OG 画像（SNS カードの大きな画像）の新規作成
- V1 のサーバー・DNS の切り替え作業そのもの（デプロイ手順は別途）
- ダークモード対応
