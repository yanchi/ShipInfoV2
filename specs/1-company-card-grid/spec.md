# Feature Specification: トップページ会社カード横並びグリッドレイアウト

**Feature Branch**: `1-company-card-grid`
**Created**: 2026-03-08
**Status**: Implemented
**Input**: User description: "トップページ（index.html.twig）のレイアウトを縦並びカードから横並びグリッドに変更する。現在は会社ごとのカードが縦に並んでいるが、横並びにすることで会社間の順番による優劣感をなくす。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 会社カードの横並び表示（Priority: P1）

訪問者がトップページを開いたとき、フェリー会社ごとのカードが横並びのグリッドで表示される。縦一列に並ぶ現状のレイアウトでは上に表示される会社が優先度が高いように見えてしまうが、横並びグリッドにすることで視覚的な優劣をなくす。

**Why this priority**: システムの中立性を担保する最重要の変更。会社間のビジネス上の公平性に直結する。

**Independent Test**: トップページにアクセスし、会社カードが左右に並んで表示されることを目視確認できる。

**Acceptance Scenarios**:

1. **Given** 複数のフェリー会社データが存在する状態で、**When** トップページを開くと、**Then** 会社カードが横方向に並んで表示される
2. **Given** 画面幅が十分なデスクトップ環境で、**When** トップページを開くと、**Then** 1行に複数社のカードが並んで表示される
3. **Given** 会社が1社のみの場合、**When** トップページを開くと、**Then** カードが1枚のみ表示される（レイアウト崩れなし）

---

### User Story 2 - モバイルでの適切な折り返し表示（Priority: P2）

スマートフォン等の狭い画面でトップページを開いたとき、カードが画面幅に合わせて適切に折り返して表示される。文字や運航状況バッジが読み取れるサイズを維持する。

**Why this priority**: モバイルユーザーの利便性。P1の横並びが崩れて使えなくなることを防ぐ。

**Independent Test**: ブラウザのデバイスエミュレーターで幅375px（iPhone SE相当）に設定してトップページを確認し、カードが読める状態で表示されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 画面幅が768px未満のモバイル環境で、**When** トップページを開くと、**Then** カードが1列に折り返して縦に並び、各カードが画面幅いっぱいに表示される
2. **Given** 画面幅が768〜991pxのタブレット環境で、**When** トップページを開くと、**Then** カードが2列で表示される

---

### User Story 3 - カード内コンテンツの維持（Priority: P3）

レイアウト変更後も、各カード内に表示される会社名・公式サイトリンク・航路一覧・運航状況バッジがすべて正しく表示される。

**Why this priority**: 既存機能の後退を防ぐデグレード防止要件。

**Independent Test**: レイアウト変更後のトップページで各カードの情報が変更前と同一であることを確認できる。

**Acceptance Scenarios**:

1. **Given** レイアウト変更後のトップページで、**When** 各カードを確認すると、**Then** 会社名・公式サイトリンク・航路名・運航状況バッジがすべて表示されている
2. **Given** 欠航・遅延・通常運航など異なるステータスの航路が存在する場合、**When** トップページを開くと、**Then** 各ステータスバッジが正しい色とテキストで表示される

---

### Edge Cases

- 会社数が0件の場合：「現在情報がありません」のアラートが表示される（既存動作を維持）
- 会社数が非常に多い場合（10社以上）：グリッドが適切に折り返してレイアウトが崩れない
- 航路が0件の会社が存在する場合：「航路情報がありません」が表示される（既存動作を維持）
- カードごとにコンテンツ量（航路数）が異なる場合：同一行内のカードは均一高さとする（航路数の差による見た目のガタつきを防ぐ）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: トップページの会社カードは横並びグリッド（CSS Grid または Flexbox wrap）で表示されること
- **FR-002**: デスクトップ（画面幅992px以上）では1行に最大3社のカードが並ぶこと
- **FR-003**: タブレット（画面幅768〜991px）では1行に最大2社のカードが並ぶこと
- **FR-004**: モバイル（画面幅767px以下）では1列（1社）で表示されること
- **FR-005**: 各カードの内部コンテンツ（会社名リンク、公式サイトリンク、航路一覧、運航状況バッジ）は変更しないこと
- **FR-006**: 会社データが0件の場合は既存のアラートメッセージを引き続き表示すること

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: トップページで複数の会社カードが横方向に並んで表示され、縦スクロール量が削減される
- **SC-002**: どの会社カードも画面上の表示位置による視覚的な優劣が生じない（同一行に並ぶ）
- **SC-003**: 画面幅375px（モバイル）でカード内のテキストと運航状況バッジが読み取れる状態で表示される
- **SC-004**: 同一行に並ぶカードの高さが揃っており、航路数の差による段差が生じない
- **SC-005**: 変更前後で各カードに表示される情報（会社名・航路名・ステータスバッジ）に差異がない
