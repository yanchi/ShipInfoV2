# Feature Specification: 港ごとのページと、検索で選ばれるタイトル・説明文

**Feature Branch**: `18-port-seo-pages`
**Created**: 2026-11-04
**Status**: Draft
**Input**: User description: "検索流入を増やすための SEO 改善。(1) 港ごとにインデックスされるページを作る：今は港の絞り込みが Cookie・クエリで、canonical がクエリ無しのため /ports の1ページしかインデックスされない。出発港ごとに /ports/{slug}（例: /ports/tokunoshima）の URL を作り、ページごとに港名入りの title・h1・description（例:「徳之島発 フェリー運航状況（今日・明日）」）を付け、sitemap.xml に載せる。既存の /ports の保存（Cookie）機能は壊さない。(2) トップ・会社ページ・港別ページの title と description に「今日・明日」「リアルタイム」「欠航・遅延」を入れる。表記は正しい「運航」のままにし、「運行」は使わない（隠しテキスト・meta keywords も使わない）。V1 から引き継いだ site_top_title・title_suffix を変えるので twig.yaml と関連 spec（specs/7-v1-branding）も直す。"

## 概要

V2 に切り替えたあとの検索の状況（Search Console、2026-11-01 の1日分）：表示 171 回、クリック 4 回、CTR 2.3%、平均掲載順位 7.8 位。

上位のクエリ：

| クエリ | クリック | 表示 |
|--------|---------:|-----:|
| 鹿児島-奄美 フェリー 運行 状況 今日 | 1 | 2 |
| マリックスライン 運行 状況 明日 | 1 | 1 |
| マリックスライン 運行 状況 リアルタイム | 0 | 11 |
| マリックスライン 運行 状況 | 0 | 8 |
| 奄美航路 運行状況 | 0 | 7 |
| 徳之島 フェリー 運行 状況 今日 | 0 | 7 |
| 鹿児島-奄美 フェリー 運行状況 | 0 | 6 |

ここから分かること：

- **島・港の名前で探している**（徳之島・奄美）。でも今インデックスされるページは、トップ・港別（1ページ）・会社別の4つしかない。港の絞り込みはクエリと Cookie で切り替えていて、canonical はクエリ無しの `/ports` を指す。そのため「徳之島発の便」だけのページは検索エンジンから見えない
- **「今日」「明日」「リアルタイム」を付けて探している**。このサイトは今日から4日分を毎時更新していて、まさにその答えになる。でもタイトルにその語が無い
- 検索では「運**行**状況」と打つ人が多い。ただ、Google はもう「運航」と同じ意味として扱って表示している。だから正しい表記の「運**航**」を変えない

## Clarifications

### Session 2026-11-04

- Q: 画面に出る文言を検索語に合わせて「運行」にするか → A: しない。正しいのは「運航」なので、タイトル・説明文・本文はすべて「運航」のまま。見えない文字（隠しテキスト・meta keywords）で「運行」を足すこともしない

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 島の名前で検索して、その港を出る便がすぐ分かる（Priority: P1）

「徳之島 フェリー 運航状況 今日」と検索した旅行者が、検索結果に「徳之島（亀徳港）発 フェリー運航状況（今日・明日）」というページを見つける。開くと、亀徳港を出る便だけが日付ごとに並び、今日・明日に欠航・遅延があるかがすぐ分かる。

**Why this priority**: 検索の表示回数を増やす一番の手段。港ごとのページが無いと、島の名前で探す人にはサイトのトップしか見せられず、順位もクリックも伸びない。

**Independent Test**: 各港のページの URL を開き、タイトル・見出し・説明文にその港（と島）の名前が入っていること、その港を出る便だけが出ることを確かめる。sitemap.xml にすべての港のページが載っていることを確かめる。

**Acceptance Scenarios**:

1. **Given** 出発港の一覧にある港（例: 亀徳）、**When** その港のページの URL を開くと、**Then** 「全港」ではなくその港を出る便だけが、港別ページと同じ形（日付ボタン・異常の要約・便の一覧）で出る
2. **Given** 港のページ、**When** `<head>` を見ると、**Then** タイトル・説明文・og:title・og:description に港の名前（島で呼ばれる港は島の名前も。例:「徳之島（亀徳港）」）が入っていて、canonical と og:url はその港のページ自身の URL になっている
3. **Given** 港のページ、**When** 画面の大見出しを見ると、**Then** 港（と島）の名前が入っている（例:「徳之島（亀徳港）発の運航状況」）
4. **Given** `/sitemap.xml`、**When** 開くと、**Then** 出発港の一覧にあるすべての港のページの URL が載っている
5. **Given** 港のページの URL、**When** 見ると、**Then** 港をローマ字で表す短い英小文字の名前になっていて（例: `/ports/tokunoshima`）、港の内部の番号は出ない
6. **Given** 港別ページの絞り込みで港を1つ選んで「表示」したとき、**When** 移った先を見ると、**Then** その港のページの URL になっている（ブックマーク・共有しても同じ港が出る）

---

### User Story 2 - 検索結果のタイトルを見て「今日・明日の運航状況が分かる」と思える（Priority: P1）

「マリックスライン 運航状況 明日」と検索した人が、検索結果に並ぶこのサイトのタイトル・説明文を見て、今日・明日の欠航・遅延がリアルタイムで分かるページだと判断し、クリックする。

**Why this priority**: 今も検索結果には出ている（表示 171 回）のにクリックが 2.3% しかない。タイトル・説明文を変えるだけでクリックを増やせて、手間が小さい。

**Independent Test**: トップ・港別・会社別・各港のページの `<head>` を見て、タイトル・説明文が下の決まりどおりになっていることを確かめる。

**Acceptance Scenarios**:

1. **Given** トップページ、**When** タイトルを見ると、**Then** 「今日・明日」と「運航状況」が入っていて、扱う区間（鹿児島〜奄美・沖縄）が分かる
2. **Given** 会社別ページ（例: マリックスライン）、**When** タイトルを見ると、**Then** 先頭が会社名で、そのあとに「運航状況（今日・明日）」が続く
3. **Given** どのページでも、**When** 説明文を見ると、**Then** 「今日・明日」「欠航・遅延」「リアルタイム」または「毎時更新」が自然な文で入っている
4. **Given** どのページでも、**When** タイトル・説明文・本文・`<head>` 全体を見ると、**Then** 「運行」という表記はどこにも無く、meta keywords や見えない文字も無い

---

### User Story 3 - 今まで使っていた港別ページ・保存した港がそのまま使える（Priority: P2）

港別ページで「亀徳」を保存していた利用者が、変更後も今までどおりトップと港別ページで保存した港の便を見られる。古い形の URL（港の番号をクエリに付けた URL）をブックマークしていた人も、同じ港のページにたどり着く。

**Why this priority**: 新しいページを足しても、今の利用者の使い方を壊さないための条件。

**Independent Test**: 港を保存した状態でトップと `/ports` を開き、今までどおり保存した港の便が出ることを確かめる。古い形の URL を開き、その港のページへ移ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 港を保存している利用者、**When** トップと `/ports` を開くと、**Then** 変更前と同じく保存した港の便が出る
2. **Given** 港を保存している利用者、**When** 別の港のページを開くと、**Then** URL の港の便が出る（保存した港には切り替わらない）。保存した条件はそのまま残る
3. **Given** 古い形の URL（例: `/ports?port=3`）、**When** 開くと、**Then** 同じ港のページへ恒久的に転送される。方向の指定があれば、転送先でも同じ方向で絞り込まれる
4. **Given** 港別ページの絞り込みで「全港」を選んだとき、**When** 移った先を見ると、**Then** 今までどおり `/ports`（全港）になる
5. **Given** 港のページ、**When** 絞り込みのフォームを見ると、**Then** その港が選ばれた状態で出て、保存・保存を解除も今までどおりできる

### Edge Cases

- 出発港の一覧に無い名前の港のページ（例: `/ports/xxx`、廃止した港）を開いたら、「ページが見つかりません」を出す（全港の一覧などへ勝手に飛ばさない）。検索エンジンに存在しないページと伝わるようにする
- 古い形の URL で、出発港の一覧に無い番号（例: `/ports?port=999`）を開いたら、転送せずに今までどおりの扱い（全港を表示）にする
- 古い形の URL で港を指定せず方向だけ指定した場合（例: `/ports?dir=up`）は、転送せず今までどおり `/ports` で表示する
- 港のページに方向の指定（上り・下り）が付いていても、canonical と og:url は方向の指定を除いた港のページの URL にする（同じ港のページが方向ごとに別のページとして扱われないように）
- 鹿児島・那覇のように島ではない港は、港の名前だけでよい（「鹿児島（鹿児島新港）」のように重ねない）
- 港の URL に使う名前は、一度決めたら変えない（変えると検索の評価とブックマークが失われる）。港の表示名を直しても URL は変わらないこと
- タイトルが長すぎて検索結果で切れても、先頭だけで何のページか分かる（港名・会社名・「運航状況」を先に置く）

## Requirements *(mandatory)*

### Functional Requirements

**港ごとのページ**

- **FR-001**: 出発港の一覧（港別ページの絞り込みに出る港）にある港ごとに、`/ports/<港の名前>` のページを出すこと。`<港の名前>` は港をローマ字で表す英小文字の短い名前とすること
  - 鹿児島 → `kagoshima`、名瀬 → `naze`、亀徳 → `kametoku`、和泊 → `wadomari`、与論 → `yoron`、本部 → `motobu`、那覇 → `naha`
  - 港の名前は港の内部番号とは別に持ち、港の表示名を直しても変わらないこと
- **FR-002**: 港のページには、港別ページの絞り込みでその港を選んだときと同じ内容（日付ボタン・異常の要約・その港を出る便）を出すこと。方向の指定（上り・下り）は今までどおり付けられること
- **FR-003**: 港のページのタイトルは「<港の呼び名>発 フェリー運航状況（今日・明日）」で始めること。説明文には港の呼び名・扱う会社・「今日・明日」「欠航・遅延」を入れること
- **FR-004**: 港の呼び名は、島の港は「<島の名前>（<港の名前>港）」、それ以外は港の名前とすること
  - 名瀬 → 奄美大島（名瀬港）、亀徳 → 徳之島（亀徳港）、和泊 → 沖永良部島（和泊港）、与論 → 与論島（与論港）、本部 → 沖縄・本部港、鹿児島 → 鹿児島、那覇 → 那覇
- **FR-005**: 港のページの大見出しに港の呼び名を出すこと（例:「徳之島（亀徳港）発の運航状況」）
- **FR-006**: 港のページの canonical・og:url は、方向の指定などを除いた港のページ自身の URL にすること
- **FR-007**: 出発港の一覧に無い名前の港のページは「ページが見つかりません」を返すこと
- **FR-008**: `/sitemap.xml` に、出発港の一覧にあるすべての港のページを載せること（今のトップ・港別・各社ページに加える）

**今の港別ページ・保存した港との関係**

- **FR-009**: `/ports`（港の指定なし）は今までどおりとすること。保存した港があればその港、無ければ全港を出す
- **FR-010**: 港のページでは、URL の港を表示すること（保存した港より URL を優先する。今のクエリ指定と同じ）。保存した条件は書き換えないこと
- **FR-011**: 港別ページの絞り込みで港を1つ選んで「表示」「保存」したときの移り先は、その港のページ（方向の指定があれば付ける）にすること。「全港」のときは今までどおり `/ports` にすること。保存・保存を解除の動き（いつ保存し、いつ消すか）は変えないこと
- **FR-012**: 古い形の URL（港の番号をクエリで指定した `/ports`）で、出発港の一覧にある港を指定していたら、その港のページへ恒久的に転送すること。方向の指定があれば転送先にも付けること。出発港の一覧に無い番号や、港を指定していないときは転送しないこと
- **FR-013**: トップの「保存した港の今日の便」の「4日分を見る」は、保存した港が1つならその港のページ（方向の保存があれば付ける）へのリンクにすること。港を保存していない（方向だけの保存）なら今までどおり `/ports` へのリンクにすること
- **FR-013a**: 港別ページ（全港・各港とも）に、すべての港のページへの普通のリンク（フォームを使わずにたどれるリンク）を並べること。いま見ている港はリンクにせず、見ていることが分かるようにすること（今の絞り込みは送信フォームなので、検索エンジンは港のページへたどれない）
- **FR-013b**: 港のページでも、ヘッダーのナビの「港別」をいまいるページとして示すこと

**タイトル・説明文**

- **FR-014**: トップページのタイトルを「鹿児島〜奄美・沖縄 フェリー運航状況（今日・明日）| 欠航・遅延をリアルタイム確認」にすること
- **FR-015**: トップ以外のページのタイトルの後ろに付ける共通の文を「 | 鹿児島〜奄美・沖縄フェリー運航情報」にすること
- **FR-016**: 会社別ページのタイトルは「<会社名> 運航状況（今日・明日）」に共通の文を付けたもの、港別ページ（全港）は「港別 フェリー運航状況（今日・明日）」に共通の文を付けたものにすること
- **FR-017**: すべてのページの説明文に「今日・明日」と「欠航・遅延」を入れ、「リアルタイム」か「毎時更新」も入れること。トップの説明文には「奄美航路」も入れること。説明文は文として自然であること（語を並べるだけにしない）
- **FR-018**: タイトル・説明文・画面の文言は「運航」と書き、「運行」と書かないこと。meta keywords や見えない文字で検索語を足さないこと
- **FR-019**: og:title・og:description は、今までどおりタイトル・説明文と同じにすること

**変えないもの**

- **FR-020**: ヘッダーのサイト名（「鹿児島〜沖縄・奄美大島 フェリー運航情報」）・og:site_name・著作権表示・OG 画像は変えないこと
- **FR-021**: V1 から引き継ぐと決めたタイトルの文言（7-v1-branding の FR-004）を、この機能で置き換えたことを 7-v1-branding の spec に書き残すこと

### Key Entities

- **港**: 今ある港に、URL に使う名前（英小文字・変えない・重複しない）と、島の名前（島の港だけ）を足す。港の呼び名は港の名前と島の名前から作る

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 出発港の一覧にあるすべての港（7港）に、それぞれのページがあり、sitemap.xml に 7 港すべてが載っている
- **SC-002**: 公開から 4 週間以内に、7 港のページすべてが検索エンジンにインデックスされている
- **SC-003**: 公開から 4 週間後の 28 日間で、検索結果のクリック率が 2.3% から 4% 以上に上がる
- **SC-004**: 公開から 4 週間後の 28 日間で、島・港の名前を含む検索（例:「徳之島 フェリー」）で港のページが表示されている
- **SC-005**: 全ページのタイトル・説明文・本文に「運行」が 0 件
- **SC-006**: 港の保存・トップの「保存した港の今日の便」・古い形の URL が、変更後もすべて今までどおり使える（既存のテストがすべて通り、古い形の URL は同じ港のページに移る）

## Assumptions

- 出発港は今の 7 港（鹿児島・名瀬・亀徳・和泊・与論・本部・那覇）。港が増えたら、URL に使う名前と島の名前を同じ決まりで足す
- 港の呼び名に使う島の名前は、一般に呼ばれている名前（奄美大島・徳之島・沖永良部島・与論島）とする。本部港は沖縄本島にあるが「沖縄本島（本部港）」は検索されにくいので「沖縄・本部港」とする
- 「リアルタイム」は、毎時更新して最終確認時刻を出していることを指す。今の説明文でも使っている表現なので続けて使う
- 港のページは港別ページの絞り込みを1つの港で固定したもので、新しい情報は足さない
- 港ごとのページを足しても、ヘッダーのナビの項目は変えない（「港別」から各港へは、港別ページの中のリンクか絞り込みで移る）
- 効果（SC-002〜SC-004）は Search Console で確かめる

## Out of Scope

- 「運行」表記の追加（画面・見えない文字のどちらでも）
- 到着港・航路（区間）ごとのページ
- 構造化データ（パンくずなど）の追加
- 港ごとの OG 画像
- ヘッダーのナビに各港へのリンクを足すこと（各港へのリンクは港別ページの中に置く。FR-013a）
- 被リンクを増やす活動など、サイトの外での取り組み
